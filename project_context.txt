# CLAUDE.md — 서울 창업 입지 탐색기

서울시 상권 CSV 7종 + 네이버 뉴스로 창업 검토 후보 상권×업종(11종)을 제시하는
Streamlit 대시보드. **계약 정본은 `DEV_SPEC.md`** — 이 파일과 충돌하면 DEV_SPEC이 우선.

## 강제 규약
- 원본 읽기는 `common/loader.py`의 `load()`만 (cp949 + 코드 컬럼 dtype=str 강제)
- 조인은 코드 컬럼으로만. **영역-상권은 `on="상권_코드"` 단일 키** (분기 컬럼 없음)
- 상권 단위 컬럼(인구·가구)은 조인 후 sum() 금지 — 업종 수만큼 복제되어 있음
- 분위수는 drop_duplicates("상권_코드") 후 계산
- 분기 산술 금지 ("20254" 다음은 "20261") — loader.QUARTERS 인덱스로
- 비율 지표는 분모 0 방어 (loader.safe_ratio 사용)
- 산출 파일은 utf-8-sig
- 유형 7종·**업종 11종**·가중치(인구 1:1:1, 점수 0.6:0.4)는 DEV_SPEC §5 확정값 — 임의 변경 금지
- 앱은 로직과 UI 분리: 데이터 변환·점수 재계산은 `app/logic.py`, 위젯은 `app/main.py`

## 환경 (uv)
- 실행은 전부 `uv run python ...` 경유. 패키지 추가는 pip 금지 — `uv add`만
  (pyproject.toml + uv.lock 변경을 같은 커밋으로, 사람이 커밋)

## 검증 (완료 판정 = 이것의 green)
- uv run python seams/check_master.py   # data/master.csv
- uv run python seams/check_scores.py   # data/scores.csv (공급갭>0 후보만 담김)
- uv run python seams/check_news.py     # data/news.csv (0행이면 red, 일부 상권 미보유는 정상)
- uv run python seams/check_app.py      # app/logic.py 계약 (화면이 아니라 로직)

## 금지
- seams/ 검증 스크립트 수정 금지 (검사가 틀렸다고 판단되면 멈추고 사람에게 보고)
- **app/logic.py 에 streamlit import 금지** — 위젯·레이아웃은 app/main.py 에만
- **common/viz.py 는 B·C조 공유 파일 — 오너 1인만 수정** (다른 조는 요청)
- 뉴스 수집 주력은 scripts/scrape_news.py (requests+bs4). collect_news.py는 API 백업 —
  주력/백업을 임의로 바꾸지 말 것 (전환은 수집 지역 수 미달 시 코드가 자동으로 한다)
- 자기 조 오너십 밖 파일 수정 금지
- git commit·push 금지 — 커밋·push·머지는 전부 사람이 직접 (에이전트는 파일 수정까지만)

# 서울 창업 입지 탐색기 — 공용 개발 문서 (DEV_SPEC)

**v6 · 11종 한정 통일판** · 2026-08-20 · 확인: (6명 전원 이름 기입)

> **지위**: 브라운필드(구현 존재) · 판정일 2026-08-20 ·
> 근거: `master.csv` 산출·`check_master` green 확인, `scores.csv` v5 기준 산출본 존재.
> v6은 그 위에 얹는 개정이므로 **재실행 없이는 반영되지 않는다.**

> **이 문서의 역할**: 조 사이를 오가는 데이터·규칙의 **계약서**다.
> 여기 적힌 스키마·정의·수치는 전부 실제 데이터로 실행 검증된 값이다.
>
> **변경 규약**: 계약(스키마·컬럼·정의·임계값)을 바꿀 때는 ① 생산 조와 소비 조 합의 →
> ② 이 문서 개정 커밋 → ③ 전원 알림 순서다. **코드를 먼저 고치는 것 금지.
> 말로만 합의한 변경은 커밋 전까지 무효.**
>
> **검증 스크립트 수정 금지.** 단 계약이 회의에서 바뀌면 검사도 같이 바뀐다 —
> 그 갱신은 팀장이 전담하고 커밋 후 전원에게 알린다.

### 미채움 항목

`상주인구-상권`의 `아파트_가구_수`는 **21개 분기 전 상권에서 0**이며
`비_아파트_가구_수 == 총_가구_수`가 100% 일치한다. **분석에 사용하지 않고 master에도 싣지 않는다.**

> 이런 결함은 결측 검사로 잡히지 않는다(0은 결측이 아니다). **새 컬럼을 지표에 쓰기 전에는
> 반드시 분포를 먼저 확인한다** — `describe()` 또는 `value_counts()` 1회.

### 직장인구-상권 주의사항

- **분석 구간 5개 분기의 값이 전부 동일함을 실측 확인** (원 데이터가 연 1회 갱신).
  분기별 변화 분석에 쓸 수 없고 상권 특성(스냅샷)으로만 사용한다.
- 조인 키는 `상권_코드` + `기준_년분기_코드`. master 결합 시 미매칭 상권 제거
  (인구 3종 결합 후 실측: 상권 1,562 → 1,558, 19개 제거는 인구 3종 합산 기준).
- **스케일 주의**: 중앙값 494 · 최대 199,667 (404배). 원단위 min-max로는 정규화값
  중앙값이 0.0025가 되어 지표에서 사라진다 → **log1p 후 정규화 필수** (§5-3).

KEY_DTYPES = {"상권_코드": str, "서비스_업종_코드": str, "기준_년분기_코드": str,

## 3. 공통 규약

1. **조인 정본은 코드다.** `상권_코드`·`서비스_업종_코드`로만 조인한다. 명칭 컬럼은 표시용.

   `common/viz.py`는 B·C조 공유 파일이므로 **오너 1인만 수정**한다(다른 조는 요청).

11. **에이전트 산출 diff는 주니어의 PR로 취급.** 본인이 설명할 수 있어야 머지한다.
12. **예상 질문 3개 + 답**을 각자 4일차 저녁까지 노션에.

### 아티팩트 3 — `data/news.csv` (뉴스 담당 → C조)

> **비어 있어도 되는 유일한 아티팩트다.** 기사 없는 상권은 정상 상태이므로, 게이트는

- **셀렉터는 구조 기반**: 1일차 스파이크에서 클래스명 셀렉터가 기사 제목 대신 "네이버뉴스"

**정밀도 필터 4단계 (순서대로)**

| 단계 | 필터 | 방법 |
|---|---|---|
| 1 | 경제지 화이트리스트 | **링크 도메인 판정** (한국경제·매일경제·서울경제·머니투데이·아시아경제·파이낸셜뉴스·이데일리) — 도메인 판정은 언론사 표기 변형에 흔들리지 않는다 |
| 2 | 최근 90일 | 검색 URL 기간 파라미터 + 날짜 텍스트 파싱('N일 전'/'YYYY.MM.DD.'), 수집일 기준 상대 계산 (하드코딩 금지) |
| 3 | 관련도 점수 | 제목에 지역명 2점 > 요약 앞 60자 1점 > **0점 탈락** · 상권 키워드(상권/창업/점포/임대료/골목/매출/개업/폐업/오픈/입점) +1 |
| 4 | 지역당 상위 3건 | 점수 → 최신순 |

> 실측 표본 검증: 제목에 지역명이 있는 경제지 기사만 통과, "지역이 스쳐 지나가는"

> `scrape_news.py`가 `collect_news.py`(검색 API, `.env`에 키 필요)를 자동 호출하고
> 전환 사실을 stderr에 남긴다. 사람의 판단에 걸어두면 마감 직전에 일어나지 않는다.
> 두 경로는 필터를 `scripts/news_filter.py` **한 모듈로 공유**한다. 각자 구현하면
> 한쪽만 고쳐지고, 두 경로의 산출 스키마는 같은데 필터 결과만 달라져 게이트가
> 그 차이를 잡지 못한다. 두 스크립트 모두 `collect_all()`로 수집만 하고 저장은

> 그러면 90일이 지난 기사가 오늘 기사로 둔갑해 게이트를 통과한다.

### 아티팩트 4 — `app/logic.py` (C조 내부 계약)

게이트 `uv run python seams/check_app.py`

앱은 **로직과 UI를 분리한다.** `app/logic.py`에 streamlit을 import하지 않고 데이터 로드·
필터·종합점수 재계산·상세 조회를 순수 함수로 둔다. `app/main.py`는 위젯과 레이아웃만
담당한다.

**분리 이유**: 게이트가 없으면 C조 에이전트 지시서의 `[수용 기준]`(§3-1)을 "화면이 잘
뜨면"으로밖에 쓸 수 없다. 분리하면 아래가 기계 검사가 된다.

- 기본 가중치(0.6:0.4) 재계산 결과 == `scores.csv`의 종합점수
  → `build_scores.py`와 앱이 **같은 공식을 쓴다는 증명**
- 가중치 (1,0)·(0,1)에서 각 지표 단독 순위와 일치
- 가중치 (0,0)·빈 필터 결과·기사 없는 상권에서 예외 없음

**함수 계약**: `load_scores` / `load_news` / `rescore(df, w_gap, w_stab)` /
`filter_candidates(df, 업종, 유형, 자치구)` / `summary(df)` /
`news_for(news, 상권_코드, n)` / `reverse_lookup(df, 상권_코드, n)`

> `rescore`는 **재정규화하지 않는다.** 필터 후 min-max를 다시 걸면 조건을 좁혔을 때
> 순위가 뒤집혀 설명할 수 없는 화면이 된다.

### 5-2. 유형 분류 (확정 7종)

**선처리**: 상권_구분_코드_명이 발달상권/전통시장/관광특구면 유형 = "발달상권형"/
"전통시장형"/"관광특구형"으로 즉시 확정. **규칙 분류는 골목상권(1,026개)에만 적용.**

```python
유입강도   = 총_유동인구_수 / 총_상주인구_수
가구당인구 = 총_상주인구_수 / 총_가구_수
청년비율   = (연령대_20 + 연령대_30_상주인구_수) / 총_상주인구_수
```

| 순서 | 유형 | 판정 조건 |
|---|---|---|
| ① | **유입 집중형** | 유입강도 상위 25% |
| ② | 청년 밀집형 | 유입강도 25~75% **AND** 청년비율 상위 25% |
| ③ | 가족 주거형 | 유입강도 하위 50% **AND** 가구당인구 상위 50% |
| ④ | 일반 주거·생활형 | 그 외 |

**실측 분포 (20261, 골목상권 1,026개)**

| 유형 | 상권 수 | 유입강도(중앙) | 가구당인구 | 청년비율 |
|---|---|---|---|---|
| 가족 주거형 | 325 | 194 | **2.06** | 0.27 |
| 일반 주거·생활형 | 321 | 307 | 1.80 | 0.31 |
| 유입 집중형 | 257 | **587** | 1.71 | 0.30 |
| 청년 밀집형 | 123 | 310 | 1.52 | **0.46** |

- 임계값은 골목상권 분포의 **사분위수** (절대값 하드코딩 금지)
- **v2의 오피스 밀집형·상업·번화형이 "유입 집중형"으로 통합**되었다. 둘을 가르던 유일한
  기준이 주중집중도였고, 그 축을 제외했기 때문이다.
- **직장인구 확보 시**: `직장인구 / 상주인구`로 오피스형을 다시 분리할 수 있다.
  주중집중도보다 직접적인 근거이며, 확정 시 유형 7종 → 8종으로 이 문서를 개정한다.
- **분모 0 방어**: 총_상주인구_수·총_가구_수가 0인 행 제외 후 분위수 계산.
- ⚠️ 상주인구가 극소인 상권에서 유입강도가 폭발한다(실측 최대 32,408). 사분위 기반이라
  순위는 안전하나 화면 표시 시 상한 처리.

### 5-3. 수요 지표 — 인구 3종 로그 정규화 가중합 (1:1:1 확정)

```python
유효수요 = (w_r × minmax(log1p(총_상주인구_수))
         + w_w × minmax(log1p(직장인구))
         + w_f × minmax(log1p(총_유동인구_수))) / (w_r + w_w + w_f)
공급밀도 = 전체_점포_수 / 유효수요
```

**확정: `w_r : w_w : w_f` = 1 : 1 : 1** (킥오프 결정 6 · 미결 아님)

> 후보 3안(1:1:1 / 2:1:1 / 1:1:0.5)을 실측 비교한 결과 상위 상권이 거의 동일했다.
> 차이가 없으면 근거를 못 대는 숫자를 만들 이유가 없으므로 균등으로 확정했다.

- **`log1p`는 필수다. 표결 대상이 아니었다.** 직장인구는 중앙값 494인데 최대 199,667
  (404배)이라, 원단위 min-max로는 정규화값 중앙값이 **0.0025**가 되어 가중치를 아무리
  줘도 지표에서 사라진다. 로그를 빼면 직장인구를 편입한 근거 자체가 무효가 된다.
- **가중치 합으로 나눈다.** 안 나누면 유효수요가 0~3 범위가 되어 공급밀도의 절대 크기가
  달라진다(공급갭은 비율이라 순위는 같지만, 산점도 x축 눈금이 문서와 어긋난다).
- **설계 근거**: 상주인구 단독을 분모로 쓰면 명동·강남역 등 유입형 상권의 공급밀도가
  폭증해 "전부 공급 과잉"으로 판정된다(실측: 상주 3명·유동 5.6만 상권 존재).
- **직장인구 편입 근거 (발표용)**: 상주↔유동은 상관 0.72로 크게 겹치는 반면
  직장인구는 상주와 0.23, 유동과 0.39로 독립적인 수요 정보를 담는다.

> ⚠️ v5 이전 이 절은 `log1p`와 가중치 합 나누기가 빠진 채 `× 10000`이 붙어 있었고,
> 가중치도 `⬜ 미확정`으로 남아 있었다(회의록 결정 6·기획서와 불일치).
> **정본은 회의록 결정 6이다.**

### 5-4. 공급 갭

```
공급갭 = (동일유형 중앙 공급밀도 − 해당 상권 공급밀도) / 동일유형 중앙 공급밀도
```

같은 유형×업종의 중앙값을 기준선으로 삼는다. **서울 전체를 한 줄로 세우면 "번화가가
좋다"는 자명한 결론으로 수렴하므로, 비교군을 먼저 정의한 뒤 그 안에서 갭을 탐지한다.**

> **`scores.csv`는 공급갭 > 0 인 행만 담는다.** 필터 없이 점수만으로 뽑으면 상위 100개 중
> 43개가 공급 과잉 조합(공급갭 최소 −2.91)으로 나온다 — 프로젝트 목적과 정면으로 어긋난다.

### 5-5. 안정성 — 행정동 × 외식 11종 (v6 변경)

```python
# ⚠️ v6: 분모·분자 모두 화이트리스트 11종으로 한정한다
m11 = master[master["서비스_업종_코드_명"].isin(whitelist)]      # §5-1 적용
q4  = m11[m11["기준_년분기_코드"].isin(["20252","20253","20254","20261"])]

행정동_폐업률 = q4.groupby("행정동_코드").apply(
    lambda g: g["폐업_점포_수"].sum() / g["전체_점포_수"].sum() * 100)
안정성점수   = 1 − minmax(행정동_폐업률)
```

- 대상 분기: 20252~20261 (4개)
- **집계 단위가 행정동인 근거 (v3, 유지)**: 상권×업종 개별 폐업률은 분산의 84%가 설명되지
  않는 노이즈다(업종이 7.4%, 상권이 8.4% 설명). 표본이 작아 우연이 순위가 된다.
- **업종을 11종으로 한정하는 근거 (v6, 신설)**: 전 업종 집계는 그 행정동의 학원·부동산중개·
  미용실 폐업까지 분모·분자에 넣는다. "이 동네에서 **외식업이** 얼마나 버티는가"를 묻는
  지표가 되어야 상권×업종 후보의 안정성 근거로 읽힌다.
  발표 질문 *"왜 학원 폐업률이 제 치킨집 입지 판단에 들어가나요"* 에 답이 없던 유일한 지점이었다.

### 5-6. 종합점수

```
종합점수 = w1 × 갭점수 + w2 × 안정성점수      (기본 0.6 : 0.4)
```

**기본값 0.6:0.4 근거 (v6 재확인 완료 — 유지)**: 안정성을 낮게 둔 이유는 행정동 단위라
같은 행정동 상권들의 안정성 점수가 동일해지기 때문이다 (0.5:0.5면 사실상 동점 처리기).

**⚠️ 상위 10 비교 수치가 11종 전환으로 바뀌었다 (3일차 실측).**

| 비교 | v5 (62종 기준) | **v6 (11종 기준)** |
|---|---|---|
| 0.6 vs 0.7 | 10/10 동일 | **9/10** |
| 0.6 vs 0.5 | 7/10 | **8/10** |

> v5의 *"0.6과 0.7은 상위 10이 **완전히** 동일"* 은 11종 기준에서 성립하지 않는다(9/10).
> **주 근거를 겹침 수가 아니라 변별력 격차로 옮긴다** — 안정성점수 대 갭점수 표준편차 비가
> 2.1배(0.106 vs 0.220) → **2.5배**(0.087 vs 0.219)로 벌어졌다. 변별력이 낮은 지표에
> 절반의 무게를 주는 0.5:0.5가 부적절하다는 근거는 오히려 강해졌다.
> (0.5와의 겹침이 7→8로 늘었지만, 그건 겹침 수가 이 판단의 주 근거가 아니라는 뜻이다.)

**⚙️ 정규화 방식은 min-max를 유지한다 (v6 명시적 선택).** 안정성이 뭉치는 실제 원인은
가중치가 아니라 폐업률 최대값(11.94, 중앙의 3.3배)이 스케일을 차지하는 것이다. 분위수
정규화나 상위 클립으로 완화할 수 있으나 **채택하지 않는다** — ① min-max는 단조변환이라
안정성 **단독 순위는 바뀌지 않는다**(영향은 가중합에만), ② 사용자가 슬라이더로 안정성을
올리는 경로가 이미 있다, ③ 4일차 동결을 앞두고 계약 변경 + 재실행 + 게이트 재확인을
추가할 이득이 없다. **덜 예민한 것이지 틀린 것이 아니다** — 한계로 명시하고 넘어간다.

각 지표를 minmax로 0~1 정규화 후 가중 합산. **가중치는 코드에 고정하지 않고 앱 슬라이더
인자로 받는다.** 팀이 가중치를 정하면 "왜 그 숫자인가"에 답이 없다.

## 6. 앱 구성 (C조)

지도를 제외하므로 **산점도가 메인 시각화**다.

| 화면 | 내용 |
|---|---|
| ① 후보 탐색 | 사이드바(업종·유형 필터 + **슬라이더 2개**) → 후보 목록 표 + 상단 요약 지표 |
| ② 상권 포지셔닝 산점도 | x=유효수요, y=점포당매출, size=점포수, color=유형, 중앙값 사분면 구분선 |
| ③ 상세 패널 | 유형·판정 근거 / 연령 구성 / 동일 유형 중앙값 대비 공급밀도 / 행정동 폐업률 / **요일별 매출 표(월~일)** / 업종의 서울시 전체 추이 / 최근 3개월 기사 3건 |
| ④ 역방향 탐색 | 상권 선택 → 공급 부족 업종 Top 5 (기능 우선순위 최하위, 지연 시 제외) |

**연동 원칙**: 사이드바 조건 변경 → 종합점수 재계산 → 목록 표 + 산점도 + 요약 지표가
**동시에** 갱신된다. 한 요소만 따로 반응하는 구간을 만들지 않는다.

**일관성**: 4개 화면이 동일 골격(좌측 조건 / 우측 결과). 유형 색상은 `common/viz.py`의
`TYPE_COLORS`를 노트북과 공유. 화면 문구는 "추천"이 아닌 **"검토 후보"**로 통일.

**빈 상태**: 조건에 맞는 후보가 0건이면 빈 화면 대신 조건 완화를 안내한다.

**성능**: 로드·점수 계산은 `st.cache_data`, 슬라이더 변경 시 가중합만 재계산.
선택 상태는 `st.session_state`.

## 8. 결정 기록 (ADR)

각 설계 결정의 기술적 근거를 남긴다. 모든 수치는 실데이터 실행으로 확인한 값이다.

- **CSV 주력, API 보조**: 추정매출은 API 1,000행 제한으로 전량 호출이 비현실적.
- **inner 조인으로 업종 62종**: 매출 없는 업종은 갭 계산이 불가하므로 제외가 맞다.
- **규칙 분류 (ML 군집 대신)**: 재현·설명 가능하고 3일차 재작업 리스크가 없다.
- **아파트비율 → 가구당인구 (v2)**: `아파트_가구_수`가 전 상권·전 분기 0. 그대로 두면
  조건이 항상 참이 되어 골목상권 45%가 근거 없이 한 유형으로 몰린다(실측).
- **주중집중도 축 제외 → 유형 4종 (v3)**: 축을 화면 표시(요일별 표)로 돌리면서 오피스형과
  상업번화형을 가를 기준이 사라졌다. 직장인구 확보 시 `직장인구/상주인구`로 재분리 가능.
- **수요적합도 제외 (v3)**: 시간 제약. 더불어 선정 11종이 전부 외식·식음료라 연령 프로파일
  유사도가 0.958로, 살려도 업종 간 변별력이 거의 없었다.
- **후보_인정 폐지, 공급갭 > 0만 유지 (v3)**: 조건 계산 비용을 없애되, 필터를 완전히 빼면
  상위 100개 중 43개가 공급 과잉 조합이 된다. `공급갭 > 0`은 조건이 아니라 "무엇을 찾는가"의
  정의라서 남긴다.
- **폐업률 행정동 단위 (v3)**: 상권×업종 개별 폐업률은 분산의 84%가 노이즈다.
- **폐업률을 외식 11종 한정으로 (v6)**: 지표 계산에 11종 밖 업종이 섞이는 곳이 여기 하나
  남아 있었다(유형 분류·유효수요는 상권 단위라 업종 무관, 공급밀도·공급갭은 이미 업종별).
  전 업종 분모는 "이 동네 전체가 얼마나 버티나"를 재는데, 우리가 답하는 질문은
  "여기서 **이 외식 업종을** 열면 버티나"다. 질문과 지표를 일치시킨다.
  ⚠️ **표본 감소 위험이 있어 되돌림 기준을 먼저 고정했다**(§0-1 OPEN-1, 0값 10%).
  v3에서 행정동으로 올린 이유가 표본 부족이었으므로, 좁히는 방향 변경은 그 이유와 충돌한다.
- **파일은 62종, 필터는 소비 단계 (v6)**: "11종만 쓴다"는 결정이 "11종만 저장한다"를
  함의하지 않는다. 자르면 되돌릴 수 없고 대조군이 사라진다. 대신 **소비 규약 + 주석 의무**로
  누락과 의도를 구별한다(아티팩트 1).
- **아웃라이어 클립·분위수 정규화 미채택 (v6)**: 안정성점수 표준편차 0.087(갭 0.219)로
  뭉치는 것을 확인했고 원인도 특정했다(폐업률 최대 11.94 vs 중앙 3.597). 그럼에도 손대지
  않는다 — min-max는 단조변환이라 단독 순위 불변이고, 슬라이더가 이미 대체 경로다.
  **동결 직전에 "더 나은 것"과 "지금 틀린 것"을 구분하지 못하면 일정이 무너진다.**
  발표 예상 질문("안정성 점수가 왜 다 비슷한가요")으로 준비해 답한다.
- **무효가 된 실측값을 지우지 않고 ⬜로 남김 (v6)**: 폐업률 정의가 바뀌면서 표준편차 0.76·
  0값 1.0%·0.6:0.4 근거가 근거를 잃었다. 지우면 "값이 없다"가 되고, 두면 "틀린 값이 확정처럼
  앉아 있다"가 된다. **대조군으로 라벨링해 남기고 신규 칸을 ⬜로 여는 것**이 셋 중 유일하게
  판정 가능한 상태다.
- **업종 수를 상한이 아닌 정확값으로 검사 (v5)**: 정본 §5-1이 커피-음료를 빠뜨린 채
  10종을 나열하고 있었는데, 게이트가 `> 11`만 봐서 10종 산출이 green으로 통과했다.
  **정본이 틀렸는데 검사가 못 잡는 조합**이 이 프로젝트에서 가장 비싼 실패 유형이다.
  검사를 `!= 11`로 바꿔 미달도 red가 되게 한다.
- **앱 로직/UI 분리 (v5)**: 게이트 없이는 C조 에이전트 지시서의 수용 기준을 "화면이 잘
  뜨면"으로밖에 쓸 수 없다. 로직을 순수 함수로 빼면 기본 가중치 재계산이 `scores.csv`
  값과 일치하는지 검사할 수 있고, 이는 `build_scores.py`와 앱이 같은 공식을 쓴다는 증명이다.
- **뉴스 백업 전환 자동화 (v5)**: 전환 기준을 문서로만 두면 4일차 밤에 판단이 일어나지
  않는다. 수집 지역 20개 미만이면 코드가 API 경로를 호출하고 stderr에 기록한다.
  전환에 필요한 `collect_all()`이 백업 쪽에 없어(`main()`이 저장까지 했다) 같이 분리했다.
- **유효수요에 log1p 유지 (v5)**: 정본에서 로그가 빠져 있었다. 원단위 min-max면
  직장인구 정규화값 중앙값이 0.0025가 되어 지표에서 사라지고, "직장인구는 독립적인
  정보"라는 발표 근거가 통째로 무효가 된다. 회의록이 "표결 대상이 아니다"로 못 박은 이유다.
- **정밀도 필터 공유 모듈 (v5)**: 주력·백업이 `press_of`·`relevance`·화이트리스트·
  파라미터를 각자 들고 있었다. 두 경로의 **산출 스키마가 같아서** 게이트는 어느 쪽이
  돌았는지 구별하지 못한다 — 필터만 달라지면 조용히 다른 결과가 나온다.
  `news_filter.py`로 합치고, `collect_news.py`의 미사용 `load_master` import도 제거했다
  (`common/loader.py`에 그 이름이 없으면 import 시점에 죽어 폴백까지 함께 실패한다).
- **지도 제외 (v3)**: 5일 일정 안에서 미도입 기술의 학습·디버깅 비용이 핵심 분석 품질을 잠식할 위험이 크다고 판단, 산점도·표·필터 연동으로 대체.
  단 영역-상권 파일은 유지한다 — `행정동_코드`의 유일한 출처다.
- **뉴스 수집 requests+bs4 주력**: 1일차 스파이크에서 클래스명 셀렉터가 기사 제목 대신
  버튼 라벨을 잡는 문제 확인(44건 동일 문자열) → 도메인+텍스트 길이 기반 구조 셀렉터로
  재설계하여 해결. 검색 API는 차단·구조 변경 대비 백업 경로로 유지.
- **뉴스 정밀도 필터**: API 표본에서 관련 없는 기사가 절반가량 — "지역이 스쳐 지나가는"
  전국 기사가 원인. 제목/요약 위치 기반 관련도 점수로 해결 (표본 검증 완료).
- **인구 가중치 1:1:1**: 후보 3안의 상위 결과가 거의 동일 — 차이가 없으면 근거 없는
  숫자를 만들지 않는다. log1p는 직장인구 스케일(404배) 때문에 필수.
- **종합점수 기본 0.6:0.4**: 안정성이 행정동 단위라 뭉치는 것을 보정. v5에서는 "0.6과 0.7의
  상위 10이 완전히 동일"이 주 근거였으나 11종 전환 후 9/10으로 바뀌어, **근거를 겹침 수에서
  변별력 격차(안정성:갭 표준편차 2.5배)로 옮겼다.** 겹침 수는 표본이 바뀌면 흔들리는 근거다.
- **정적 노트북과 앱 분리**: 답하는 질문이 다르다 — 전자는 "무엇을 알아냈는가",
  후자는 "사용자가 무엇을 할 수 있는가".
- **배포 제외, 시연 영상**: 발표 당일 라이브 실패 리스크 제거.
- **가중치 슬라이더 위임**: 팀이 가중치를 고정하면 "왜 그 값인가"에 답이 없다.

# 서울 창업 입지 탐색기 (Seoul Startup Scout)

서울시 상권 공공데이터 7종을 결합해, 비슷한 성격의 상권끼리 비교했을 때
**공급이 부족하면서 폐업률이 안정적인 상권×업종 조합**을 검토 후보로 제시하는
Streamlit 대시보드.

분석 대상은 생활밀접 **외식·식음료 11종**(한식·중식·일식·양식음식점, 분식전문점,
패스트푸드점, 치킨전문점, 호프-간이주점, 제과점, 커피-음료, 반찬가게)이며,
공급밀도·폐업률·업종 추이 등 **모든 지표를 이 11종 범위 안에서 계산**한다.

> 계약 정본은 [`DEV_SPEC.md`](DEV_SPEC.md) · 결정 이력은 [`docs/킥오프_회의록.md`](docs/킥오프_회의록.md)

## 설치 및 실행

```bash
# 1. 환경 구성 (uv 필요: https://docs.astral.sh/uv/)
uv sync

# 2. 원본 데이터 배치 — data/raw/README.md 의 CSV 7종 다운로드 (cp949)

# 3. 파이프라인 실행 (각 단계 뒤 검증 스크립트가 완료 판정)
uv run python scripts/build_master.py
uv run python seams/check_master.py      # → OK 확인
uv run python scripts/build_scores.py
uv run python seams/check_scores.py      # → OK 확인

# 4. 뉴스 수집 (requests + BeautifulSoup)
uv run python scripts/scrape_news.py
uv run python seams/check_news.py        # → OK 확인
#    확보 지역 20개 미만이면 검색 API 백업 경로로 자동 전환 (.env 에 키 필요)

# 5. 참고 지표 (선택 — 없으면 상세 패널의 해당 영역만 비워진다)
uv run python scripts/build_trend.py

# 6. 앱 로직 계약 검증 + 대시보드 실행
uv run python seams/check_app.py         # → OK 확인
uv run streamlit run app/main.py
```

원본 데이터가 아직 없을 때는 계약과 동일한 형태의 가데이터로 앱을 먼저 띄울 수 있다:

```bash
uv run python scripts/make_mock.py
uv run python seams/check_app.py data/mock/scores.csv data/mock/news.csv
```

## 파이프라인

```
data/raw/ (CSV 7종, cp949)
   → build_master.py   → master.csv          (106,337행 × 77컬럼 · 상권 1,558 · 업종 62)
   → build_scores.py   → scores.csv          (후보 3,443건 · 유형 7종 · 업종 11종 · 상권 1,339)
   → scrape_news.py    → news.csv            (후보 상권 최근 3개월 경제지 기사, bs4)
   → build_trend.py    → industry_trend.csv  (업종 11종 × 5분기 = 55행, 참고 표시용)
   → app/main.py       (Streamlit)
```

`master.csv`가 62종인 것은 필터 누락이 아니라 의도다 — **결합 테이블은 원천으로 두고,
업종 한정은 소비 단계에서 적용**한다. 62종을 남겨두는 이유는 "62종 중 왜 이 11종인가"의
대조 근거가 필요하기 때문이며, 그 대조 분석 외에는 어떤 집계도 62종으로 돌리지 않는다
(`DEV_SPEC.md` 아티팩트 1의 소비 규약).

## 주요 설계

- **유형별 기준선 대비 갭 분석** — 서울 전체 순위는 "번화가가 좋다"는 자명한 결론으로
  수렴하므로, 상권을 7개 유형으로 분류한 뒤 같은 유형 안에서 공급 부족을 탐지
- **유효수요 = 상주+직장+유동 인구의 로그 정규화 균등 가중합** — 직장인구는
  상주·유동과 독립적인 수요 정보(상관 0.23/0.39). 로그 없이는 스케일 차이(404배)로
  직장인구가 지표에서 사라진다
- **안정성 = 행정동 × 외식 11종의 4분기 폐업률** — 개별 상권×업종 폐업률은 분산의 84%가
  노이즈임을 실측으로 확인하고 집계 단위를 행정동으로 상향했고, 집계 대상 업종은 분석
  대상과 일치시켰다. "이 지역에서 **외식업이** 얼마나 버티는가"를 재는 지표다
- **가중치는 팀이 아니라 사용자가 정한다** — 갭·안정성 슬라이더 2종(기본 0.6:0.4).
  팀이 고정하면 "왜 그 숫자인가"에 답이 없다
- **데이터 품질 자동 검증** — 조 간 인계는 `seams/` 검증 스크립트 통과가 완료 기준.
  산문 보고가 아니라 게이트 출력이 완료의 증거다

"""app/logic.py — 대시보드 로직 (Streamlit 비의존 · C조 오너)

**이 파일에 streamlit을 import하지 않는다.** 위젯·레이아웃은 `app/main.py`,

from __future__ import annotations

STR_COLS = [

NEWS_COLS = ["상권_코드", "행정동_base", "제목", "언론사", "날짜", "링크"]

# ── 로드 ──────────────────────────────────────────────────────────────
def load_scores(path: str = SCORES_PATH) -> pd.DataFrame:
    """후보 테이블 로드."""
    return pd.read_csv(path, encoding="utf-8-sig", dtype={c: str for c in STR_COLS})


def load_trend(path: str = TREND_PATH) -> pd.DataFrame:
    """업종별 서울시 전체 개·폐업률 추이."""
    try:

# ── 점수 재계산 ───────────────────────────────────────────────────────
def rescore(
    df: pd.DataFrame,
    w_gap: float = W_GAP_DEFAULT,
    w_stab: float = W_STAB_DEFAULT,
) -> pd.DataFrame:
    """슬라이더 가중치로 종합점수 가중합 재계산."""
    total = w_gap + w_stab
    if total <= 0:
        w_gap, w_stab, total = W_GAP_DEFAULT, W_STAB_DEFAULT, 1.0
    g, s = w_gap / total, w_stab / total

    out = df.copy()
    out["종합점수"] = (g * out["갭점수"] + s * out["안정성점수"]).round(4)
    return out.sort_values("종합점수", ascending=False, kind="mergesort")


# ── 필터 ──────────────────────────────────────────────────────────────
def filter_candidates(
    df: pd.DataFrame,
    업종: list[str] | None = None,
    유형: list[str] | None = None,
    자치구: list[str] | None = None,
) -> pd.DataFrame:
    """사이드바 다중 필터 적용."""
    out = df
    if 업종:
        out = out[out["서비스_업종_코드_명"].isin(업종)]
    if 유형:
        out = out[out["유형"].isin(유형)]
    if 자치구:
        out = out[out["자치구_코드_명"].isin(자치구)]
    return out


def summary(df: pd.DataFrame) -> dict:
    """상단 요약 메트릭 계산."""
    if df.empty:
        return {"후보_수": 0, "평균_종합점수": 0.0, "상권_수": 0, "평균_공급갭": 0.0}
    return {
        "후보_수": int(len(df)),
        "평균_종합점수": float(df["종합점수"].mean()),
        "상권_수": int(df["상권_코드"].nunique()),
        "평균_공급갭": float(df["공급갭"].mean()),
    }


# ── 상세 패널 ─────────────────────────────────────────────────────────

def news_for(news: pd.DataFrame, 상권_코드: str, n: int = 3) -> pd.DataFrame:
    """해당 상권 기사 조회."""
    if news.empty:
        return news
    return news[news["상권_코드"] == 상권_코드].sort_values("날짜", ascending=False).head(n)

def trend_for(trend: pd.DataFrame, 업종명: str) -> pd.DataFrame:
    """해당 업종 분기별 추이 조회."""
    if trend.empty:
        return trend
    return trend[trend["서비스_업종_코드_명"] == 업종명]


# ── 역방향 탐색 ───────────────────────────────────────────────────────
def reverse_lookup(df: pd.DataFrame, 상권_코드: str, n: int = 5) -> pd.DataFrame:
    """④ 역방향 탐색 — 상권 기준 공급 부족 업종 Top N."""
    return df[df["상권_코드"] == 상권_코드].nlargest(n, "종합점수")


# ── 입지 탐색 ─────────────────────────────────────────────────────────
def forward_lookup(
    df: pd.DataFrame,
    업종명: str,
    유형: list[str] | None = None,
    자치구: list[str] | None = None,
    n: int = 10,
) -> pd.DataFrame:
    """입지 탐색 — 업종 기준 검토 후보 상권 Top N. `reverse_lookup`의 대칭.

    scores.csv는 공급갭>0 후보만 담기므로(§4 아티팩트 2) 특정 업종의 후보가
    없거나 극소수인 것은 **정상 상태**다. 화면은 이를 빈 결과로 안내한다.
    업종을 고정하면 상권_코드가 유일해지므로 결과는 상권 단위 비교표가 된다.
    """
    out = filter_candidates(df, 업종=[업종명], 유형=유형, 자치구=자치구)
    return out.nlargest(n, "종합점수")

def _candidate_options(scores: pd.DataFrame) -> pd.DataFrame:
    """선택 상자용 상권×업종 후보를 중복 없이 생성."""
    cols = ["상권_코드", "상권_코드_명", "서비스_업종_코드", "서비스_업종_코드_명"]
    options = scores[cols].drop_duplicates(["상권_코드", "서비스_업종_코드"]).copy()
    options["label"] = (
        options["상권_코드_명"].astype(str)
        + " · "
        + options["서비스_업종_코드_명"].astype(str)
    )
    return options.sort_values("label", kind="stable").reset_index(drop=True)

"""common/loader.py — 원본 CSV 로더.

모든 원본 읽기는 이 모듈을 통한다. 개별 pd.read_csv 직접 호출 금지
(인코딩·dtype 누락이 조인 실패의 최대 원인).
"""
from __future__ import annotations
import os
import pandas as pd

RAW_DIR = "data/raw/"
ENCODING = "cp949"

# 코드 컬럼은 반드시 문자열. 정수로 읽히면 앞자리 0이 소실되어 조인이 깨진다.
KEY_DTYPES = {
    "상권_코드": str, "서비스_업종_코드": str, "기준_년분기_코드": str,
    "자치구_코드": str, "행정동_코드": str, "상권_구분_코드": str, "서울시_코드": str,
}

# 분석 대상 분기 (상권×업종 데이터 제공 구간). 문자열 산술 금지 — 이 리스트의 인덱스로만 처리.
QUARTERS = ["20251", "20252", "20253", "20254", "20261"]
QUARTERS_4 = ["20252", "20253", "20254", "20261"]   # 폐업률 4분기 평균용


def load(name: str, raw_dir: str = RAW_DIR, **kw) -> pd.DataFrame:
    """서울시 상권분석서비스 CSV를 읽는다. 두 가지 파일명 형식을 모두 허용:
    ① 서울시_상권분석서비스_{name}_.csv   ② 서울시 상권분석서비스({name}).csv (포털 원본)
    """
    candidates = [
        f"{raw_dir}서울시_상권분석서비스_{name}_.csv",
        f"{raw_dir}서울시 상권분석서비스({name}).csv",
    ]
    for path in candidates:
        if os.path.exists(path):
            return pd.read_csv(path, encoding=ENCODING, dtype=KEY_DTYPES, **kw)
    raise FileNotFoundError(
        f"data/raw/ 에서 '{name}' CSV를 찾지 못했다. 허용 이름:\n  "
        + "\n  ".join(candidates))

def load_master(path: str = "data/master.csv") -> pd.DataFrame:
    """산출된 master.csv 를 읽는다 (utf-8-sig + 코드 컬럼 str)."""
    return pd.read_csv(path, encoding="utf-8-sig", dtype=KEY_DTYPES)


def load_whitelist(path: str = "config/업종_whitelist.csv") -> list[str]:
    """확정 분석 업종 목록."""
    return pd.read_csv(path)["서비스_업종_코드_명"].tolist()


def safe_ratio(numer: pd.Series, denom: pd.Series) -> pd.Series:
    """분모 0을 NaN으로 처리한 나눗셈.

    유입강도·가구당인구·청년비율은 전부 나눗셈이다. 분모 0을 막지 않으면
    inf가 생기고 분위수 계산이 조용히 왜곡된다.
    """
    return numer / denom.replace(0, pd.NA)

def setup(font_size: int = 11) -> None:
    """한글 폰트 + 마이너스 기호 + seaborn 테마를 한 번에 설정한다."""
    system = platform.system()
    if system == "Darwin":
        family = "AppleGothic"
    elif system == "Windows":
        family = "Malgun Gothic"
    else:                                  # Linux (배포·CI 환경)
        family = "NanumGothic"
    plt.rc("font", family=family, size=font_size)
    plt.rcParams["axes.unicode_minus"] = False   # 음수 부호가 □로 깨지는 것 방지
    sns.set_theme(style="whitegrid", font=family, rc={"axes.unicode_minus": False})


def palette(types) -> list:
    """유형 리스트를 받아 TYPE_COLORS 순서대로 색 리스트를 반환한다.
    seaborn의 palette= 인자에 그대로 넣는다."""
    return [TYPE_COLORS.get(t, "#8C8C8C") for t in types]

필터 비용은 한 줄이라 시간 부담이 없다. (점포 수 필터는 불필요함이 확인됨 —
상위 100개 중 점포 1~2개짜리가 **0개**)

### 결정 6. 유효수요 — **인구 3종 로그 정규화 가중합**

```python
유효수요 = (w_r × minmax(log1p(상주인구))
         + w_w × minmax(log1p(직장인구))
         + w_f × minmax(log1p(유동인구))) / (w_r + w_w + w_f)
공급밀도 = 전체_점포_수 / 유효수요
```

**확정: `w_r : w_w : w_f` = 1 : 1 : 1**

| 후보 | 유효수요 상위 5 상권 |
|---|---|
| **1 : 1 : 1** | 잠실 관광특구 / 강남역 / 역삼역 / 선릉역 / 포스코사거리 |
| 2 : 1 : 1 (상주↑) | 잠실 관광특구 / 강남역 / 역삼역 / 뱅뱅사거리 / 선릉역 |
| 1 : 1 : 0.5 (유동↓) | 잠실 관광특구 / 강남역 / 역삼역 / 잠실역 / 가산디지털단지 |

> **어느 쪽을 골라도 상위 결과가 거의 같다.** 차이가 없으면 근거를 못 대는 숫자를
> 만들 이유가 없으므로 **균등(1:1:1)으로 확정**했다.

**로그 변환은 표결 대상이 아니다 (설명만)**: 직장인구는 중앙값 494인데 최대 199,667(404배)이라
원단위 min-max로는 정규화값 중앙값이 **0.0025**가 되어 가중치를 아무리 줘도 지표에서 사라진다.

**직장인구를 넣은 근거 (발표용)**: 성분 간 상관을 보면 상주↔유동은 0.72로 크게 겹치는 반면
직장인구는 상주와 0.23, 유동과 0.39로 **독립적인 정보**를 담고 있다.

### 결정 7. 종합점수 기본 가중치 — **갭 : 안정성**

```python
종합점수 = w_gap × 갭점수 + w_stb × 안정성점수      # 앱 슬라이더가 덮어씀
```

**확정: `w_gap : w_stb` = 0.6 : 0.4**

| 후보 | 상위 10 평균 공급갭 | 평균 폐업률 | 평균 점포 수 |
|---|---|---|---|
| 0.5 : 0.5 | 0.81 | 1.28 | 4.3 |
| **0.6 : 0.4 (채택)** | 0.85 | 1.58 | 5.1 |
| 0.7 : 0.3 | 0.85 | 1.58 | 5.1 |

**근거**: 0.6과 0.7은 상위 10개가 **완전히 동일**하다. 결과가 같다면 덜 극단적인 쪽이
방어하기 쉽다 — "왜 갭에 7할이냐"보다 "6:4로 갭을 조금 더 봤다"가 낫다.
0.5:0.5와는 상위 10 중 7개만 겹친다.

안정성 쪽을 낮게 두는 이유는 결정 3의 부작용이다. 행정동 단위라 같은 행정동 상권들은
안정성 점수가 **동일**해져, 0.5:0.5면 사실상 동점 처리기가 된다.

> 이 값은 슬라이더 초기 위치이며 고정값이 아니다. 사용자가 조절할 수 있고, 3일차에 실제 분포 확인 후 초기값을 재조정할 수 있다.

### 결정 12. AI 협업 그라운드 룰

- **커밋은 각자 손으로.** AI는 파일 수정까지, `git add`부터는 사람. 커밋하려면 diff를 보게
  되어 코드에 대한 이해가 팀 전체에 유지된다.
- **`seams/` 검증 스크립트 수정 금지.** 통과 안 되면 검사를 고치는 게 아니라 팀장에게 보고한다.
  **단 계약이 회의에서 바뀌면 검사도 같이 바뀐다 — 그 갱신은 팀장이 전담하고 커밋 후 공지한다.**
- 지시서 5줄 양식: `[배경] [목표] [수용 기준] [제약] [확인 명령]`.
  수용 기준은 반드시 기계 검사로 적는다 — "잘 동작하면"은 에이전트의 자기 판정을 믿는 것이다.
- 각자 자기 파트 **예상 질문 3개 + 답**을 4일차 저녁까지 노션에.
  발표 슬라이드는 자기 파트를 자기가 만들고 자기가 말한다.

### 결정 13. 뉴스 수집 — **requests + BeautifulSoup 주력, 검색 API 백업**

1일차 스파이크에서 발견된 셀렉터 문제를 해결하여 **스크래핑을 주력 경로로 확정**하고,
차단·페이지 구조 변경에 대비해 검색 API를 백업 경로로 준비한다.

**스파이크에서 발견·해결한 문제 (기술적 도전과 해결)**
- 초기 클래스명 셀렉터가 기사 제목 대신 "네이버뉴스" 버튼 라벨을 잡는 문제 확인
  (수집 44건 전부 동일 문자열) — 자주 바뀌는 클래스명에 의존한 것이 원인
- **구조 기반 셀렉터로 재설계**: 경제지 도메인을 가리키면서 텍스트 15자 이상인 링크로
  제목을 판별한다. "네이버뉴스"(6자) 같은 버튼 라벨은 길이 조건에서 걸러진다
- 검색 API 백업(`collect_news.py`)은 동일한 정밀도 필터를 공유한다 —
  날짜는 검색 URL 기간 파라미터(수집일 상대 계산)와 결과 내 날짜 텍스트
  ('N일 전' / 'YYYY.MM.DD.') 파싱을 병행한다

**수집 사양 (확정)** — 주력: `scripts/scrape_news.py` · 백업: `scripts/collect_news.py`(검색 API)

| 항목 | 내용 |
|---|---|
| 출처 | 네이버 뉴스 검색 (search.naver.com) — requests + BeautifulSoup |
| 매너 | 요청 간 `time.sleep(1)` 이상 · 브라우저 User-Agent · 첫 페이지만 |
| 검색 단위 | **행정동 base** — 행정동명에서 숫자 제거 (`성수1가1동`→`성수동`, `망원1동`→`망원동`) |
| 쿼리 | `"서울 {행정동_base} 상권"` |
| 기간 | 수집일 기준 90일 (pubDate 파싱, **하드코딩 금지**) |
| 대상 | `scores.csv` 종합점수 상위 100개 상권이 속한 행정동 |
| 저장 | 지역 기사를 소속 상권들로 전개 — `상권_코드, 행정동_base, 제목, 언론사, 날짜, 링크` |

### 결정 14. 뉴스 정밀도 필터 — **4단계**

표본 실측에서 확보율은 충분하나 **관련 없는 기사가 절반가량 섞이는 문제**를 확인했다
(예: 전국 유통 기사에 "성수동 팝업" 한 줄 → 성수동 기사로 수집됨). 4단계 필터를 확정한다.

| 단계 | 필터 | 방법 |
|---|---|---|
| 1 | 경제지 화이트리스트 | **링크 도메인으로 판정** (hankyung.com→한국경제 등 7개 매핑) — 언론사 표기 변형에 흔들리지 않음 |
| 2 | 최근 90일 | 검색 기간 파라미터 + 날짜 텍스트 파싱('N일 전'/'YYYY.MM.DD.'), 수집일 기준 상대 계산 |
| 3 | 관련도 점수 | 제목에 지역명 **2점** > 요약 앞 60자에 지역명 **1점** > 없으면 **0점 탈락**. 상권 키워드(상권/창업/점포/임대료/골목/매출/개업/폐업/오픈/입점) 포함 시 +1 |
| 4 | 지역당 상위 3건 | 점수 → 최신순 정렬 후 3건 |

**실측 표본 검증 결과**: 버거킹 성수(한국경제·제목에 지역명) ✅ 채택 /
CJ온스타일 패션(마이데일리) ❌ / KBS 이코노픽(본문이 강릉 얘기) ❌ / 중소기업뉴스 ❌ /
"네이버뉴스" 버튼 라벨 ❌(제목 길이 필터) — 의도대로 무관 기사와 비기사 요소가 걸러짐을 확인.

> 제목·요약의 `<b>` 태그와 HTML 엔티티는 저장 전 제거한다.
> **C조 필수 처리**: 상권_코드가 `news.csv`에 없으면 "최근 3개월 관련 기사 없음" 표시
> (정상 상태이지 버그가 아니다).

# 1. 프로젝트 개요

## 프로젝트명

**서울 창업 입지 탐색기 (Seoul Startup Scout)**
— 서울시 상권 데이터 기반 창업 검토 후보 상권·업종 탐색 대시보드

## 주제 선정 배경

예비 창업자가 입지를 고를 때 참고할 공공데이터는 이미 공개되어 있으나, 점포·매출·인구·공간 정보가 서로 다른 파일에 흩어져 있어 결합 없이는 "이 동네에 이 업종이 부족한가"를 판단할 수 없다. 서울시가 제공하는 공식 시각화도 자치구 단위 현황 조회에 머물러, 실제로 점포를 낼 상권 단위의 비교는 어렵다.

또한 단순히 매출이 높은 곳을 나열하면 "번화가가 좋다"는 이미 아는 결론으로 수렴한다. 의미 있는 판단은 **비슷한 성격의 상권끼리 비교했을 때 상대적으로 공급이 부족한 곳**을 찾는 데서 나온다.

본 프로젝트는 흩어진 공공데이터를 상권 단위로 결합하고, 상권을 성격별로 분류해 비교 기준선을 만든 뒤, 그 기준선 대비 공급이 부족하면서 폐업률이 안정적인 조합을 검토 후보로 압축하는 것을 문제로 정의한다.

## 팀원 구성 (6명 / 2단계 운영)

**1단계 (1일차 ~ 2일차 오전): 데이터 단계 — 전원 공동 수행**
전원이 함께 데이터 수집·전처리·결합·품질 검증과 스키마 확정을 수행한다. 전 팀원이 데이터 구조를 직접 다루고 시작하므로, 이후 단계에서 지표·화면이 데이터와 어긋나는 소통 비용을 줄인다.

**2단계 (2일차 오후 ~): 분석·개발 분화**

## 보조 데이터 — 네이버 뉴스

후보 상권별 최근 3개월 경제지 기사(제목·언론사·날짜·링크)를 별도 테이블로 수집한다. 핵심 파이프라인과 분리되어 수집 상태가 핵심 기능에 영향을 주지 않는다.

**수집 방식의 검증과 개선 (기술적 도전과 해결)**

수집은 **requests + BeautifulSoup 웹 스크래핑**으로 수행한다. 1일차 스파이크에서 초기 구현을 실측한 결과, 클래스명 기반 셀렉터가 기사 제목 대신 "네이버뉴스" 링크 버튼 라벨을 잡는 문제를 확인하였다(수집 44건 전부 동일 문자열) — 자주 바뀌는 클래스명에 의존한 것이 원인이다. 이에 **구조 기반 셀렉터로 재설계**하였다: 경제지 도메인을 가리키면서 텍스트가 15자 이상인 링크로 기사 제목을 판별한다. "네이버뉴스"(6자) 같은 버튼 라벨은 길이 조건에서 자연히 걸러진다. 요청 간 1초 이상 간격과 브라우저 User-Agent를 유지하며 검색 첫 페이지만 수집한다. 차단이나 페이지 구조 변경에 대비해 **네이버 검색 API를 백업 경로**로 준비하고(동일한 정밀도 필터 공유), API 키는 `.env`로 관리한다. 전환은 사람의 판단이 아니라 **코드가 자동으로** 수행한다 — 수집 완료 시점에 확보 지역이 20개 미만이면 스크립트가 API 경로를 호출하고 전환 사실을 기록한다.

**정밀도 필터 4단계**: 표본 실측에서 관련 없는 기사가 절반가량 섞이는 문제(전국 유통 기사에 지역명이 한 줄 스쳐가는 유형)를 확인하고 필터를 설계하였다.

1. **경제지 화이트리스트** — 링크 도메인으로 판정 (한국경제·매일경제·서울경제·머니투데이·아시아경제·파이낸셜뉴스·이데일리). 도메인 판정은 언론사 표기 변형에 흔들리지 않는다
2. **최근 90일** — 검색 기간 파라미터와 결과 내 날짜 텍스트('N일 전'/'YYYY.MM.DD.') 파싱, 수집일 기준 상대 계산 (날짜 하드코딩 금지)
3. **관련도 점수** — 제목에 지역명(2점) > 요약 앞부분에 지역명(1점) > 없으면 탈락. 상권 키워드(상권·창업·점포·임대료 등) 포함 시 가점
4. **지역당 상위 3건** — 점수·최신순

검색 단위는 상권이 속한 **행정동**(숫자 제거 base명)으로 하여 기사 확보율을 높이고, 수집된 지역 기사를 소속 상권들로 전개해 저장한다. API 키는 `.env`로 관리하여 저장소에 노출하지 않는다.

## 전처리 계획

- **결합**: 상권 코드·업종 코드·분기 코드 기준 결합. 영역-상권은 시간 무관 파일(상권당 1행)이므로 상권 코드 단일 키로 조인 — 실측 1,650개 상권 전부 매칭
- **결측**: 매출·인구 데이터에 결측 없음(사전 검증). 인구 3종과 매칭되지 않는 상권은 유효수요 계산이 불가하므로 결합 단계에서 제거 (실측 19개 상권, 최종 1,558개)
- **미채움 항목 배제**: `아파트_가구_수`는 전 분기·전 상권 0으로 확인되어 미사용
- **분석 업종 한정의 적용 범위**: 선정 11종 한정은 후보 산출뿐 아니라 **폐업률 집계·업종 추이·
  분포 그래프 등 지표를 만드는 모든 단계에 동일하게 적용**한다. 결합 테이블 자체는 62종을
  유지하여 "62종 중 왜 이 11종인가"의 대조 근거로 남기되, 그 대조 목적 외에 62종을 집계에
  사용하지 않는다
- **집계 주의**: 상권 단위 컬럼(인구·가구)은 결합 후 업종 수만큼 복제되므로 합계 금지, 분위수는 상권별 중복 제거 후 계산
- **분모 0 방어**: 유입강도·가구당인구·청년비율은 나눗셈 지표이므로 분모 0을 결측 처리 후 계산
- **품질 자동 검증**: 결합 테이블·후보 테이블의 스키마를 자동 검사하는 스크립트를 두고, 조 간 데이터 전달 시 **검증 통과를 완료 기준**으로 운영

## 상권 유형 분류 (규칙 기반, 7종)

머신러닝 군집 대신 **해석 가능한 규칙 기반 분류**를 채택한다 — 임계값이 사분위수로 고정되어 재현 가능하고, 발표에서 기준을 명확히 설명할 수 있으며, 유형 재조정 시 재작업 리스크가 없다.

**선처리**: 발달상권·전통시장·관광특구는 상권 구분 자체를 유형으로 사용한다 — 규모·성격이 다른 상권을 골목상권과 같은 분위수로 묶으면 비교 기준이 왜곡되기 때문. 규칙 분류는 골목상권(1,026개)에만 적용한다.

```python
유입강도   = 총_유동인구_수 / 총_상주인구_수
가구당인구 = 총_상주인구_수 / 총_가구_수
청년비율   = (20대 + 30대 상주인구) / 총_상주인구_수
```

| 순서 | 유형             | 판정 조건 (위에서부터 첫 매칭)            |
| ---- | ---------------- | ----------------------------------------- |
| ①    | 유입 집중형      | 유입강도 상위 25%                         |
| ②    | 청년 밀집형      | 유입강도 25~75% AND 청년비율 상위 25%     |
| ③    | 가족 주거형      | 유입강도 하위 50% AND 가구당인구 상위 50% |
| ④    | 일반 주거·생활형 | 그 외                                     |

**축 선정 시 데이터 검증**: 당초 네 번째 축으로 아파트 가구 비율을 계획하였으나, 사전 검증에서 해당 컬럼이 전 기간 0으로 채워져 있음을 확인하였다. 그대로 적용하면 "비율 ≥ 중앙값(0)" 조건이 항상 참이 되어 골목상권의 45%가 근거 없이 한 유형으로 분류된다. 이에 **가구당 상주인구 수**로 대체하였다 — 1인 가구 중심 상권과 가족 세대 중심 상권을 구분하며, 원래 의도한 정주형 주거 상권을 실제 값으로 포착한다.

**실측 분포 (2026년 1분기, 골목상권 1,026개)**: 가족 주거형 325 / 일반 주거·생활형 321 / 유입 집중형 257 / 청년 밀집형 123. 각 유형의 중앙값이 자기 판정 축에서 전체 중앙값 대비 뚜렷하게 벗어남을 확인하였다 (가족형 가구당인구 2.06 vs 전체 1.79, 청년형 청년비율 0.46 vs 0.30).

## 파생 지표

### ① 유효수요 — 인구 3종 가중 통합

```python
유효수요 = (minmax(log1p(상주인구)) + minmax(log1p(직장인구)) + minmax(log1p(유동인구))) / 3
공급밀도 = 전체_점포_수 / 유효수요
```

- **직장인구를 편입한 근거**: 상주↔유동 인구는 상관 0.72로 크게 겹치는 반면, 직장인구는 상주와 0.23, 유동과 0.39로 **독립적인 수요 정보**를 담는다
- **로그 변환 근거**: 직장인구는 중앙값 494 대비 최대 199,667(404배)로 분포가 극단적이라, 원단위 정규화로는 값이 지표에서 사라진다
- **가중치 균등(1:1:1) 근거**: 후보 3안(1:1:1 / 2:1:1 / 1:1:0.5)을 실측 비교한 결과 상위 상권이 거의 동일 — 차이가 없다면 근거를 제시할 수 없는 숫자를 임의로 정하지 않는다
- 직장인구는 원 데이터가 연 1회 갱신되어 분석 구간 내 값이 동일하므로, 추이가 아닌 **상권 특성(스냅샷)**으로만 사용한다

### ② 공급 갭

```
공급갭 = (동일유형 중앙 공급밀도 − 해당 상권 공급밀도) / 동일유형 중앙 공급밀도
```

같은 유형×업종의 중앙값을 기준선으로 삼는다. 서울 전체를 한 줄로 세우면 "번화가가 좋다"는 자명한 결론으로 수렴하므로, **비교군을 먼저 정의한 뒤 그 안에서 갭을 탐지**한다.

**후보 테이블은 공급갭 > 0 인 조합만 담는다.** 필터 없이 점수만으로 정렬하면 상위 100개 중 43개가 공급 과잉 조합으로 나타남을 실측으로 확인하였다 — "공급이 부족한 곳을 찾는다"는 목적과 어긋나므로, 이 조건은 필터가 아니라 서비스가 찾는 대상의 정의에 해당한다.

### ③ 안정성 — 행정동 단위 폐업률

```python
# 분모·분자 모두 분석 대상 외식 11종으로 한정한다
행정동_폐업률 = 해당 행정동 4분기 (11종 폐업 점포 합) / (11종 전체 점포 합) × 100
안정성점수   = 1 − minmax(행정동_폐업률)     # 방향 반전 — 검증 스크립트가 상관 부호로 자동 검출
```

**집계 단위 선정 근거**: 상권×업종 개별 폐업률은 분산의 84%가 어느 차원으로도 설명되지 않는 노이즈였다(업종 7.4%, 상권 8.4% 설명). 조합당 점포 수가 적어 우연이 순위가 되는 구조다. 상권(표준편차 1.65)·행정동(0.76)·자치구(0.35)를 비교하여, 0값 비율(1.0%)과 변별력의 균형이 맞는 **행정동 단위**를 채택하였다.

**업종 범위 선정 근거**: 지역 단위로 집계할 때 대상 업종을 전 업종으로 두면 해당 행정동의 학원·부동산중개·미용실 폐업까지 분모와 분자에 포함된다. 본 서비스가 답하는 질문은 "이 지역에서 **이 외식 업종을** 열었을 때 버티는가"이므로, 질문과 지표의 대상을 일치시켜 **분석 대상 11종으로 한정**하여 집계한다.

> 업종을 좁히면 지역당 표본이 줄어 폐업률이 다시 0에 몰릴 수 있으므로 — 행정동 단위로 올린 이유가 애초에 표본 부족이었다 — **되돌림 기준을 측정 전에 고정**하였다: 0값 비율이 10%를 초과하면 전 업종 기준으로 환원한다. **실측 결과 0값 1.5%(6/389 행정동)로 기준을 크게 밑돌았고, 표준편차는 0.76에서 1.375로 오히려 증가**하여 11종 한정을 확정하였다. 외식업 폐업률이 전 업종 평균보다 높고 지역 편차도 크다는 의미로, 변별력이 개선된 결과다.

### ④ 종합점수

```
종합점수 = 0.6 × 갭점수 + 0.4 × 안정성점수     (기본값 — 사용자가 슬라이더로 조절)
```

- 기본 0.6:0.4 근거: 행정동 단위 특성상 같은 행정동 상권들의 안정성 점수가 동일해져, 균등 가중 시 안정성이 사실상 동점 처리기가 된다. 안정성 점수와 갭 점수의 표준편차 격차가 2.5배(0.087 vs 0.219)로, 변별력이 낮은 지표에 절반의 무게를 두는 것은 타당하지 않다. 0.6과 0.7은 상위 10개 중 9개가 겹쳐 실질 차이가 작으므로 덜 극단적인 쪽을 택하였다
- 가중치를 팀이 고정하지 않고 **사용자가 슬라이더로 조절**하는 구조 — 판단 기준을 사용자에게 위임하여 로직이 투명하고 설명 가능하다

**산출 규모 (실측)**: 후보 3,443건 · 유형 7종 · 업종 11종 · 상권 1,339개

> 후보 건수·유형·상권 수는 공급 갭 기준으로 결정되므로 폐업률 집계 범위 변경의 영향을 받지 않는다. 다만 안정성 점수를 거쳐 산출되는 **종합점수와 후보 순위는 달라진다.**

# 4. 웹 애플리케이션 구현

## 설계 원칙

대시보드는 기능 나열이 아니라 하나의 탐색 흐름으로 설계한다:
**조건 설정(사이드바) → 후보 확인(목록·산점도) → 근거 확인(상세 패널) → 역방향 탐색**

- **화면 간 일관성**: 전 화면이 동일 골격(좌측 조건 입력 / 우측 결과)을 공유하고, 유형 색상은 공용 팔레트를 목록·산점도·범례에 동일 적용한다
- **연동 원칙**: 사이드바 조건 변경 → 종합점수 재계산 → 후보 목록·산점도·요약 지표가 **동시에 갱신**된다. 한 요소만 따로 반응하는 구간을 만들지 않는다
- **용어 통일**: 화면 문구는 "추천"이 아닌 **"검토 후보"**로 통일
- **성능**: 데이터 로드·점수 계산은 `st.cache_data`로 캐시, 슬라이더 변경 시 가중합만 재계산, 선택 상태는 `st.session_state`

## 화면 구성

### ① 후보 탐색 (메인)

- 사이드바: 업종·유형 필터 + **가중치 슬라이더 2종** (공급갭 / 안정성, 기본 0.6:0.4)
- 본문: 종합점수 순 후보 목록 표 + 상단 요약 지표(후보 수·평균 점수)
- 목록에 **당월 매출 금액·건수 병기** — 점수에는 넣지 않되, 공급갭이 비슷한 후보 간 규모 차이(실측 최대 20배)를 사용자가 판단할 수 있게 한다

### ② 상권 포지셔닝 — 산점도 (핵심 시각화)

- x=유효수요, y=점포당매출, size=점포수, color=상권 유형 (plotly)
- 중앙값 기준 **사분면 구분선**: 수요 높음×매출 낮음 = **기회 영역**
- 사이드바 필터가 동일하게 적용되며, 갭 분석 결과를 시각적으로 정당화하는 발표 핵심 자료

### ③ 상권 상세 패널

- 유형 이름과 판정 근거, 연령 구성 그래프, 동일 유형 중앙값 대비 공급밀도
- 소속 행정동의 4분기 폐업률, **요일별(월~일) 매출 표**
- 해당 업종의 서울시 전체 개·폐업률 추이 (참고 지표)
- **최근 3개월 경제지 기사 3건** (제목·언론사·날짜·링크) — 기사가 없는 상권은 "최근 3개월 관련 기사 없음"으로 정상 표시

### ④ 역방향 탐색

- 상권 선택 시 해당 상권에서 공급이 부족한 업종 Top 5 (메인과 동일 로직, 축만 교체 — 통합 지연 시 우선 제외 대상)

- 직장인구 비율 축 추가로 오피스형 상권 세분화 (유형 7종 → 8종)

## 한계

- **임대료·권리금 데이터 부재**로 실질 수익성 판단은 불가하며, 인과적 해석은 수행하지 않는다.
- 직장인구는 연 1회 갱신 데이터로 분석 구간 내 값이 동일하여, 변화 추이가 아닌 상권 특성으로만 반영된다.
- 제공 데이터의 아파트/비아파트 가구 구분 항목이 채워져 있지 않아, 가구당 인구 수를 대리 지표로 사용하였다.
- 행정동 단위 폐업률은 같은 행정동 내 상권 간 차이를 반영하지 못한다 — 개별 상권×업종 폐업률의 노이즈(분산의 84%)와의 절충이다.
- 안정성 점수의 분포가 좁다(표준편차 0.087, 갭 점수 0.219 대비). 폐업률 최대값이 중앙값의 3.3배(11.94 vs 3.597)여서 min-max 정규화 시 다수 지역이 좁은 구간에 압축되는 데 따른 것이다. 순위 자체는 보존되며, 사용자가 가중치 슬라이더로 안정성 비중을 높일 수 있다. 분위수 정규화 등의 보정은 후속 개선 과제로 둔다.
- 뉴스는 행정동 단위 검색의 근사이며, 관련도 필터를 거쳐도 무관 기사가 일부 포함될 수 있다.
- 상권×업종 데이터 제공 구간이 5개 분기로, 장기 추세·계절성의 완전한 반영에는 한계가 있다.
- 과거 데이터 기반 상관 분석과 후보 압축까지를 범위로 하며, **최종 판단은 현장 조사의 영역**임을 명시한다.

"""scripts/build_master.py — 1단계 산출물 data/master.csv 생성.

v4 (킥오프 확정 반영):
  - 직장인구-상권 추가 (인구 3종 가중 통합용)
  - 지도 제외 → 좌표 변환·pyproj 삭제
  - 영역-상권은 행정동_코드·자치구_코드_명만 사용 (행정동 폐업률의 유일한 출처)
  - 아파트_가구_수 제외 (21개 분기 전 상권 0)
  - 유효수요·공급밀도는 build_scores.py에서 산출 (가중치가 분석 규약에 속하므로)

원본 CSV를 data/raw/ 에 두고 실행: python scripts/build_master.py
"""
from __future__ import annotations
import os
import sys

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from common.loader import load, QUARTERS  # noqa: E402

POP_COLS = ["기준_년분기_코드", "상권_코드", "총_상주인구_수", "총_가구_수",
            "연령대_10_상주인구_수", "연령대_20_상주인구_수", "연령대_30_상주인구_수",
            "연령대_40_상주인구_수", "연령대_50_상주인구_수", "연령대_60_이상_상주인구_수"]
WORK_COLS = ["기준_년분기_코드", "상권_코드", "총_직장_인구_수"]
FLOW_COLS = ["기준_년분기_코드", "상권_코드", "총_유동인구_수"]
AREA_COLS = ["상권_코드", "자치구_코드", "자치구_코드_명",
             "행정동_코드", "행정동_코드_명", "영역_면적"]


def main() -> None:
    st = load("점포-상권")
    sal = load("추정매출-상권")
    pop = load("상주인구-상권")
    work = load("직장인구-상권")
    flo = load("길단위인구-상권")
    area = load("영역-상권")

    # 인구 3종은 21개 분기를 담고 있다 → 분석 구간으로 자른다
    pop = pop[pop["기준_년분기_코드"].isin(QUARTERS)]
    work = work[work["기준_년분기_코드"].isin(QUARTERS)]
    flo = flo[flo["기준_년분기_코드"].isin(QUARTERS)]

    key3 = ["기준_년분기_코드", "상권_코드", "서비스_업종_코드"]
    key2 = ["기준_년분기_코드", "상권_코드"]

    # 점포 × 매출: inner — 매출이 커버하는 업종(실측 62종)만 남는 것이 의도된 동작
    m = st.merge(sal.drop(columns=["상권_구분_코드", "상권_구분_코드_명",
                                   "상권_코드_명", "서비스_업종_코드_명"]),
                 on=key3, how="inner")

    m = m.merge(pop[POP_COLS], on=key2, how="left")
    m = m.merge(work[WORK_COLS], on=key2, how="left")
    m = m.merge(flo[FLOW_COLS], on=key2, how="left")

    # 영역-상권에는 기준_년분기_코드가 없다(상권당 1행) → 단일 키 조인. 실측 결측 0.
    m = m.merge(area[AREA_COLS], on="상권_코드", how="left")

    # 인구 3종 중 하나라도 없으면 유효수요를 만들 수 없다 → 제거
    before = m["상권_코드"].nunique()

          & m["총_직장_인구_수"].notna()].copy()
    dropped = before - m["상권_코드"].nunique()

    os.makedirs("data", exist_ok=True)
    m.to_csv("data/master.csv", index=False, encoding="utf-8-sig")

          f"행정동 {m['행정동_코드'].nunique()} · 인구 미매칭 제거 {dropped}개 상권")


if __name__ == "__main__":
    main()


=== .\scripts\build_scores.py ===

"""scripts/build_scores.py — 2단계 산출물 data/scores.csv 생성 (B조).

DEV_SPEC §5 분석 규약을 순서대로 구현한다. 적용 순서가 계약이다.
  5-1 업종 한정(확정 11종) → 5-2 유형 분류(7종) → 5-3 유효수요·공급밀도
  → 5-4 공급갭(>0만 유지) → 5-5 안정성(행정동) → 5-6 종합점수

실행: python scripts/build_scores.py
검증: python seams/check_scores.py
"""
from __future__ import annotations
import os
import sys

import numpy as np
import pandas as pd

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from common.loader import load_master, load_whitelist, QUARTERS_4, safe_ratio  # noqa: E402

SNAPSHOT = "20261"          # scores는 최신 분기 스냅샷 (시계열 아님)
W_POP = (1, 1, 1)           # 유효수요 가중치 w_r : w_w : w_f  ← 회의 확정값
W_SCORE = (0.6, 0.4)        # 종합점수 기본 가중치 (갭 : 안정성) ← 앱 슬라이더가 덮어씀
PRE = {"발달상권": "발달상권형", "전통시장": "전통시장형", "관광특구": "관광특구형"}


def minmax(s: pd.Series) -> pd.Series:
    return (s - s.min()) / (s.max() - s.min())


def log_norm(s: pd.Series) -> pd.Series:
    """로그 변환 후 0~1 정규화.

    직장인구는 중앙값 494인데 최대 199,667(404배)이라 원단위 min-max로는
    정규화값 중앙값이 0.0025가 되어 지표에서 사라진다. 로그가 필수다.
    """
    return minmax(np.log1p(s))


def classify(g: pd.DataFrame) -> pd.Series:
    """유형 분류 — 골목상권만. 위에서부터 첫 매칭 (적용 순서가 계약)."""
    i75, i50, i25 = g["유입강도"].quantile([0.75, 0.5, 0.25])
    y75 = g["청년비율"].quantile(0.75)
    h50 = g["가구당인구"].quantile(0.5)
    out = pd.Series("일반 주거·생활형", index=g.index)
    out[(g["유입강도"] < i50) & (g["가구당인구"] >= h50)] = "가족 주거형"
    out[(g["유입강도"].between(i25, i75, inclusive="left")) & (g["청년비율"] >= y75)] = "청년 밀집형"
    out[g["유입강도"] >= i75] = "유입 집중형"
    return out


def main() -> int:
    m = load_master()
    jong = load_whitelist()

    # --- 5-2 유형 분류: 상권 단위 1행으로 축소 후 계산 (복제 상태로 분위수 계산 금지) ---
    snap = m[m["기준_년분기_코드"] == SNAPSHOT]
    u = snap.drop_duplicates("상권_코드").copy()
    u["유입강도"] = safe_ratio(u["총_유동인구_수"], u["총_상주인구_수"])
    u["가구당인구"] = safe_ratio(u["총_상주인구_수"], u["총_가구_수"])
    u["청년비율"] = safe_ratio(u["연령대_20_상주인구_수"] + u["연령대_30_상주인구_수"],
                            u["총_상주인구_수"])
    u = u.dropna(subset=["유입강도", "가구당인구", "청년비율"])

    u["유형"] = u["상권_구분_코드_명"].map(PRE)          # 선처리 3종
    gol = u[u["유형"].isna()].copy()                    # 골목상권만 규칙 분류
    u.loc[gol.index, "유형"] = classify(gol)

    # --- 5-3 유효수요 (인구 3종 로그 정규화 가중합) ---
    wr, ww, wf = W_POP
    u["유효수요"] = (wr * log_norm(u["총_상주인구_수"])
                 + ww * log_norm(u["총_직장_인구_수"])
                 + wf * log_norm(u["총_유동인구_수"])) / (wr + ww + wf)

    # --- 5-5 안정성: 행정동 4분기 폐업률 (분자·분모 각각 합산) ---
    q4 = m[m["기준_년분기_코드"].isin(QUARTERS_4)& m["서비스_업종_코드_명"].isin(jong)]
    hd = (q4.groupby("행정동_코드")
            .apply(lambda x: x["폐업_점포_수"].sum() / x["전체_점포_수"].sum() * 100,
                   include_groups=False)
            .rename("행정동_폐업률"))

    # --- 5-1 업종 한정 + 조합 단위 조립 ---
    s = snap[snap["서비스_업종_코드_명"].isin(jong)].copy()
    s = s.merge(u[["상권_코드", "유형", "유효수요"]], on="상권_코드", how="inner")
    s = s.merge(hd, on="행정동_코드", how="left")
    s = s.dropna(subset=["행정동_폐업률"])

    # --- 5-4 공급갭 ---
    s["공급밀도"] = (s["전체_점포_수"] / s["유효수요"]).round(3)
    s["동일유형_중앙_공급밀도"] = (s.groupby(["유형", "서비스_업종_코드"])["공급밀도"]
                          .transform("median").round(3))
    s["공급갭"] = ((s["동일유형_중앙_공급밀도"] - s["공급밀도"])
                / s["동일유형_중앙_공급밀도"]).round(4)
    s = s.dropna(subset=["공급갭"])

    # scores.csv 는 후보 목록이다 — 공급 과잉 조합은 담지 않는다.
    # (필터 없이 점수만으로 뽑으면 상위 100개 중 43개가 공급갭 <= 0 이었다)
    s = s[s["공급갭"] > 0].copy()

    # --- 5-6 점수화 (방향 통일: 셋 다 높을수록 좋음) ---
    s["갭점수"] = minmax(s["공급갭"]).round(4)
    s["안정성점수"] = (1 - minmax(s["행정동_폐업률"])).round(4)   # 반전 필수
    wg, ws = W_SCORE
    s["종합점수"] = (wg * s["갭점수"] + ws * s["안정성점수"]).round(4)

    out = s[["상권_코드", "상권_코드_명", "서비스_업종_코드", "서비스_업종_코드_명", "유효수요",
             "상권_구분_코드_명", "유형", "자치구_코드_명", "행정동_코드", "행정동_코드_명",
             "공급밀도", "동일유형_중앙_공급밀도", "공급갭", "행정동_폐업률",
             "갭점수", "안정성점수", "종합점수",
             "전체_점포_수", "당월_매출_금액", "당월_매출_건수"]].copy()

    os.makedirs("data", exist_ok=True)
    out.to_csv("data/scores.csv", index=False, encoding="utf-8-sig")
    print(f"scores.csv: {len(out):,}행(후보) · 유형 {out['유형'].nunique()}종 "
          f"· 업종 {out['서비스_업종_코드'].nunique()}종 · 상권 {out['상권_코드'].nunique():,}개")
    return 0


if __name__ == "__main__":
    sys.exit(main())


=== .\scripts\collect_news.py ===

"""scripts/collect_news.py — 뉴스 수집 【백업 경로】

네이버 검색 API로 후보 상권 관련 최근 3개월 경제지 기사를 수집한다.
주력은 `scrape_news.py`(requests+bs4)이며, 이 스크립트는 스크래핑 확보 지역이
`MIN_AREAS` 미만일 때 **자동 호출**되는 백업이다 (DEV_SPEC §4 아티팩트 3).

정밀도 필터는 여기서 구현하지 않는다 — `news_filter.py`를 주력과 **공유**한다.
각자 구현하면 한쪽만 고쳐지고, 두 경로의 스키마는 같은데 결과만 달라져
게이트가 그 차이를 잡지 못한다.

사용:  NAVER_CLIENT_ID / NAVER_CLIENT_SECRET 를 .env 에 두고
       uv run python scripts/collect_news.py     # 단독 실행 (파일까지 저장)
       또는 scrape_news.py 가 collect_all() 을 호출  # 자동 전환
출력:  data/news.csv (상권_코드, 행정동_base, 제목, 언론사, 날짜, 링크)
"""
from __future__ import annotations

import os
import sys
import time
from datetime import datetime, timedelta
from email.utils import parsedate_to_datetime

import requests
from dotenv import load_dotenv

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from scripts.news_filter import (  # noqa: E402
    DAYS, PER_AREA, clean, expand, press_of, relevance, save, target_areas,
)

SLEEP = 0.3               # API 호출 간격 (일 25,000건 한도 내 매너)


def search(query: str, cid: str, secret: str) -> list[dict]:
    r = requests.get(
        "https://openapi.naver.com/v1/search/news.json",
        params={"query": query, "display": 30, "sort": "date"},
        headers={"X-Naver-Client-Id": cid, "X-Naver-Client-Secret": secret},
        timeout=10,
    )
    r.raise_for_status()
    return r.json().get("items", [])


def collect_all(scores_path: str = "data/scores.csv") -> list[dict]:
    """수집만 하고 행 목록을 돌려준다. **파일은 쓰지 않는다** —
    `scrape_news.py`가 폴백으로 호출할 때 저장 시점을 한 곳으로 모으기 위해서다.

    키가 없으면 RuntimeError를 던진다 (호출부가 전환 실패를 기록할 수 있도록).
    """
    load_dotenv()
    cid, secret = os.getenv("NAVER_CLIENT_ID"), os.getenv("NAVER_CLIENT_SECRET")
    if not (cid and secret):
        raise RuntimeError("NAVER_CLIENT_ID / NAVER_CLIENT_SECRET 가 .env 에 없다")

    area_to_sangwon = target_areas(scores_path)
    cutoff = datetime.now().astimezone() - timedelta(days=DAYS)

    rows: list[dict] = []
    for area, codes in area_to_sangwon.items():
        try:
            items = search(f"서울 {area} 상권", cid, secret)
        except requests.RequestException as e:
            print(f"[경고] {area} API 수집 실패: {e}", file=sys.stderr)
            continue
        cands = []
        for item in items:
            title, desc = clean(item["title"]), clean(item["description"])
            press = press_of(item.get("originallink", ""))
            if press is None:                      # 1) 경제지만
                continue
            pub = parsedate_to_datetime(item["pubDate"])
            if pub < cutoff:                       # 2) 최근 90일만
                continue
            score = relevance(area, title, desc)
            if score == 0:                         # 3) 관련도 0점 탈락
                continue
            cands.append((score, pub, title, press,
                          item.get("link") or item["originallink"]))
        cands.sort(key=lambda x: (-x[0], -x[1].timestamp()))   # 4) 점수 → 최신순
        picks = [(title, press, pub.strftime("%Y-%m-%d"), link)
                 for _, pub, title, press, link in cands[:PER_AREA]]
        rows += expand(area, codes, picks)
        time.sleep(SLEEP)
    return rows


def main() -> int:
    try:
        rows = collect_all()
    except RuntimeError as e:
        print(e)
        return 1
    out = save(rows)
    total = len(target_areas())
    n_area = out["행정동_base"].nunique() if len(out) else 0
    print(f"news.csv: {len(out):,}행 · 지역 {n_area}/{total} "
          f"· 상권 {out['상권_코드'].nunique() if len(out) else 0}개 "
          f"(확보율 {n_area/total:.0%})")
    print("→ 검증: uv run python seams/check_news.py")
    return 0


if __name__ == "__main__":
    sys.exit(main())


=== .\scripts\debug_scrape.py ===

"""scripts/debug_scrape.py — 뉴스 수집 0건의 원인을 어느 단계에서 막혔는지로 좁힌다.

일회용 진단 도구다. 원인이 확정되면 지운다.

실행:  uv run python -m scripts.debug_scrape
       (프로젝트 루트에서. `-m`으로 돌려야 scripts 패키지를 찾는다)
"""
from __future__ import annotations

import os
import sys
from collections import Counter
from urllib.parse import quote, urlparse

import requests
from bs4 import BeautifulSoup

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from scripts.news_filter import MIN_TITLE_LEN, press_of, relevance  # noqa: E402

AREA = sys.argv[1] if len(sys.argv) > 1 else "성수동"
UA = ("Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
      "(KHTML, like Gecko) Chrome/126.0 Safari/537.36")


def main() -> int:
    url = ("https://search.naver.com/search.naver?where=news&sm=tab_opt"
           f"&query={quote(f'서울 {AREA} 상권')}&sort=1")
    r = requests.get(url, headers={"User-Agent": UA}, timeout=10)
    print(f"[0] HTTP {r.status_code} · HTML {len(r.text):,}자 · 검색어: 서울 {AREA} 상권")
    if r.status_code != 200:
        print("    → 차단. User-Agent·간격 확인")
        return 1

    soup = BeautifulSoup(r.text, "html.parser")

    # ── 1단계: a 태그 자체가 있는가 (없으면 JS 렌더링 의심) ──────────────
    links = soup.find_all("a", href=True)
    print(f"[1] a 태그 전체: {len(links):,}개")
    if len(links) < 50:
        print("    → 너무 적다. 자바스크립트 렌더링이라 requests로는 기사가 안 온다")
        return 1

    # ── 2단계: 제목 길이 필터 ────────────────────────────────────────
    long_ = [a for a in links if len(a.get_text(" ", strip=True)) >= MIN_TITLE_LEN]
    print(f"[2] 텍스트 {MIN_TITLE_LEN}자 이상: {len(long_)}개")
    if not long_:
        print("    → 제목이 링크 텍스트에 없다. 구조가 바뀌었을 가능성")
        return 1

    # ── 3단계: 경제지 화이트리스트 (여기서 전멸하는 경우가 가장 흔하다) ──
    econ = [a for a in long_ if press_of(a["href"])]
    print(f"[3] 경제지 도메인: {len(econ)}개")

    # 어떤 도메인이 실제로 오는지 — 화이트리스트 밖이면 여기서 원인이 보인다
    domains = Counter(urlparse(a["href"]).netloc for a in long_)
    print("    실제 링크 도메인 상위 10:")
    for dom, n in domains.most_common(10):
        mark = "  ← 화이트리스트" if press_of(dom) else ""
        print(f"      {n:4d}  {dom or '(상대경로)'}{mark}")

    if not econ:
        print("    → 경제지 도메인이 0개. 링크가 네이버로 감싸져 있거나")
        print("       화이트리스트에 없는 언론사만 잡히고 있다")

    # ── 4단계: 관련도 ────────────────────────────────────────────────
    if econ:
        passed = 0
        for a in econ:
            title = a.get_text(" ", strip=True)
            block = a.find_parent(["li", "div"])
            desc = block.get_text(" ", strip=True) if block else ""
            if relevance(AREA, title, desc.replace(title, " ")[:200]):
                passed += 1
        print(f"[4] 관련도 통과: {passed}개")
        if not passed:
            print(f"    → 제목·요약 앞 60자에 '{AREA}'이 없다. 검색 단위 확인")

    # ── 표본 출력 ────────────────────────────────────────────────────
    print("\n[표본] 길이 통과한 링크 10개")
    for a in long_[:10]:
        print(f"  {a['href'][:75]}")
        print(f"    └ {a.get_text(' ', strip=True)[:50]}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())


=== .\scripts\make_mock.py ===

"""scripts/make_mock.py — 계약대로 생긴 가짜 데이터 생성 (팀장 전담).

목적은 **병렬 착수**다. 하류(EDA 4~6·앱·뉴스)가 B조의 실물 산출을 기다리지 않고
첫 시간부터 달리게 한다. 실물 전환은 경로만 바꾸면 끝이다 — 스키마가 같으므로.

실물과 **분포가 아니라 형태**만 같다. 결측·이상치를 일부러 섞어 두므로
하류는 "빈 결과", "동점", "극단값" 같은 상태를 미리 만나게 된다.

행 수를 계약 하한(2,000) 이상으로 만들기 때문에 mock으로도 게이트가 green이 된다.
즉 C조는 실물 전에 `check_scores.py`·`check_app.py`를 통과시킬 수 있다.

사용:  uv run python scripts/make_mock.py
출력:  data/mock/scores.csv · data/mock/news.csv · data/mock/industry_trend.csv
"""
from __future__ import annotations

import os
from datetime import date, timedelta

import numpy as np
import pandas as pd

N_SANGWON = 1_300
N_ROWS = 2_500
SEED = 20260820

JONG = ["한식음식점", "중식음식점", "일식음식점", "양식음식점", "분식전문점",
        "패스트푸드점", "제과점", "커피-음료", "치킨전문점", "호프-간이주점",
        "반찬가게"]                                    # 확정 11종 (DEV_SPEC §5-1)
TYPES = ["유입 집중형", "청년 밀집형", "가족 주거형", "일반 주거·생활형",
         "발달상권형", "전통시장형", "관광특구형"]      # 확정 7종 (§5-2)
GUBUN = ["골목상권", "발달상권", "전통시장", "관광특구"]
QUARTERS = ["20251", "20252", "20253", "20254", "20261"]   # 제공 5분기 (§2)
PRESS = {"한국경제": "hankyung.com", "매일경제": "mk.co.kr",
         "서울경제": "sedaily.com", "머니투데이": "mt.co.kr"}


def make_scores(rng: np.random.Generator) -> pd.DataFrame:
    rows = []
    for i in range(N_ROWS):
        s = i % N_SANGWON
        rows.append({
            "상권_코드": f"{3_000_000 + s:07d}",
            "상권_코드_명": f"목상권{s}",
            "서비스_업종_코드": f"CS{100_000 + i % 11:06d}",
            "서비스_업종_코드_명": JONG[i % 11],
            "상권_구분_코드_명": GUBUN[s % 4],
            "자치구_코드_명": f"목구{s % 25}",
            "행정동_코드": f"{11_000_000 + s % 396:08d}",
            "행정동_코드_명": f"목{s % 396}동",
            "유형": TYPES[s % 7],
            "유효수요": rng.beta(2, 3),          # §5-3 결과 — 0~1, 산점도 x축
            "공급밀도": rng.uniform(1, 50),
            "동일유형_중앙_공급밀도": rng.uniform(20, 60),
            "공급갭": rng.uniform(0.01, 0.9),
            "행정동_폐업률": rng.uniform(0, 8),
            "전체_점포_수": int(rng.integers(5, 200)),
            "당월_매출_금액": int(rng.integers(1e6, 1e9)),
            "당월_매출_건수": int(rng.integers(100, 50_000)),
        })
    df = pd.DataFrame(rows)

    # 이상치를 일부러 섞는다 — 하류가 이걸로 일한다
    df.loc[0, "공급갭"] = 0.999                       # 극단 상위
    df.loc[6, "유효수요"] = 0.998                     # 산점도 우측 극단
    df.loc[7, "유효수요"] = 0.002                     # 산점도 좌측 극단
    df.loc[1, "행정동_폐업률"] = 0.0                   # 폐업률 0 (안정성 만점)
    df.loc[2:5, "행정동_폐업률"] = df.loc[2, "행정동_폐업률"]  # 동점 — 정렬 안정성 시험

    mm = lambda s: (s - s.min()) / (s.max() - s.min())   # noqa: E731
    df["갭점수"] = mm(df["공급갭"])
    df["안정성점수"] = 1 - mm(df["행정동_폐업률"])        # 방향 반전 (§5-5)
    df["종합점수"] = 0.6 * df["갭점수"] + 0.4 * df["안정성점수"]
    return df


def make_news(scores: pd.DataFrame, rng: np.random.Generator) -> pd.DataFrame:
    """상위 상권 중 **일부에만** 기사를 붙인다.
    기사 없는 상권이 정상 상태이므로, 앱이 그 경우를 반드시 만나게 만든다."""
    top = (scores.sort_values("종합점수", ascending=False)
                 .drop_duplicates("상권_코드").head(100))
    today = date.today()
    rows = []
    for i, r in enumerate(top.itertuples()):
        if i % 3 == 0:                                # 1/3만 기사 보유
            continue
        for k in range(int(rng.integers(1, 4))):      # 1~3건
            press, dom = list(PRESS.items())[k % 4]
            rows.append({
                "상권_코드": r.상권_코드,
                "행정동_base": r.행정동_코드_명,
                "제목": f"서울 {r.행정동_코드_명} 상권 임대료 동향 분석 결과 {i}-{k}",
                "언론사": press,
                "날짜": str(today - timedelta(days=int(rng.integers(0, 89)))),
                "링크": f"https://{dom}/article/{i}{k}",
            })
    return pd.DataFrame(rows)


def make_trend(rng: np.random.Generator) -> pd.DataFrame:
    """아티팩트 5 — 업종별 서울시 전체 개·폐업률 추이 (11종 × 5분기 = 55행).

    상세 패널의 참고 표시용이다. 계산에 들어가지 않으므로 분포는 아무래도 좋고,
    **업종명 표기가 화이트리스트와 정확히 같은지**만 중요하다 —
    한 글자라도 다르면 C1의 조회가 조용히 빈 결과가 된다.
    """
    rows = []
    for jong in JONG:
        base_open = rng.uniform(1.2, 3.5)      # 업종마다 기준선이 다르게
        base_close = rng.uniform(1.0, 3.0)
        for i, q in enumerate(QUARTERS):
            rows.append({
                "서비스_업종_코드_명": jong,
                "기준_년분기_코드": q,
                "개업률": round(base_open + rng.normal(0, 0.25), 2),
                "폐업률": round(base_close + rng.normal(0, 0.25) + i * 0.05, 2),
            })
    return pd.DataFrame(rows)


def main() -> int:
    rng = np.random.default_rng(SEED)
    os.makedirs("data/mock", exist_ok=True)

    scores = make_scores(rng)
    scores.to_csv("data/mock/scores.csv", index=False, encoding="utf-8-sig")

    news = make_news(scores, rng)
    news.to_csv("data/mock/news.csv", index=False, encoding="utf-8-sig")

    trend = make_trend(rng)
    trend.to_csv("data/mock/industry_trend.csv", index=False, encoding="utf-8-sig")

    print(f"data/mock/scores.csv: {len(scores):,}행 · 유형 {scores['유형'].nunique()}종 "
          f"· 업종 {scores['서비스_업종_코드'].nunique()}종")

"""scripts/news_filter.py — 뉴스 정밀도 필터 공유 모듈 (주력·백업 공통).

`scrape_news.py`(주력, requests+bs4)와 `collect_news.py`(백업, 검색 API)가
**이 모듈 하나만** 사용한다. 필터를 각자 구현하면 한쪽만 고쳐지고,
그 차이는 게이트가 잡지 못한다 — 두 경로의 산출물 스키마는 같은데
필터 결과만 달라지기 때문이다.

계약: DEV_SPEC §4 아티팩트 3 · 정밀도 필터 4단계
"""
from __future__ import annotations

import html
import re

import pandas as pd

# ── 계약 파라미터 (DEV_SPEC §4 아티팩트 3) ──────────────────────────────
DAYS = 90                 # 최근 3개월 (수집일 기준 상대 계산 — 하드코딩 금지)
TOP_SANGWON = 100         # 종합점수 상위 상권 수
PER_AREA = 3              # 지역당 저장 기사 수
MIN_AREAS = 20            # 확보 지역이 이 밑이면 수집 실패 → 백업 경로 전환
MIN_TITLE_LEN = 15        # 제목 최소 길이 — "네이버뉴스"(6자) 버튼 라벨이 걸러지는 지점

# 경제지 화이트리스트 — **링크 도메인으로 판정**한다.
# API 응답에는 언론사 필드가 없고, 스크래핑에서는 표기가 변형되기 때문이다.
PRESS = {
    "hankyung.com": "한국경제", "mk.co.kr": "매일경제", "sedaily.com": "서울경제",
    "mt.co.kr": "머니투데이", "asiae.co.kr": "아시아경제",
    "fnnews.com": "파이낸셜뉴스", "edaily.co.kr": "이데일리",
}
# 관련도 가점 키워드
TOPIC = re.compile(r"상권|창업|점포|임대료|골목|매출|개업|폐업|오픈|입점")

TAG = re.compile(r"<[^>]+>")

OUT_COLS = ["상권_코드", "행정동_base", "제목", "언론사", "날짜", "링크"]


def clean(s: str) -> str:
    """`<b>` 태그·HTML 엔티티 제거. 저장 전 반드시 통과시킨다
    (`check_news.py`가 잔존 여부를 검사한다)."""
    return html.unescape(TAG.sub("", s)).strip()


def press_of(url: str) -> str | None:
    """1단계 — 경제지 화이트리스트. 해당 없으면 None(탈락)."""
    for dom, name in PRESS.items():
        if dom in url:
            return name
    return None


def relevance(area: str, title: str, desc: str) -> int:
    """3단계 — 관련도 점수. 0점은 탈락.

    제목에도 요약 앞부분에도 지역명이 없으면 지역이 스쳐 지나가는 기사
    (예: 전국 유통 기사에 '성수동 팝업' 한 줄)일 가능성이 높다 — 실측 확인된 패턴.
    """
    score = 0
    if area in title:
        score += 2
    elif area in desc[:60]:
        score += 1
    if score and TOPIC.search(title + " " + desc):
        score += 1
    return score


def target_areas(scores_path: str = "data/scores.csv") -> pd.Series:
    """수집 대상: 종합점수 상위 상권이 속한 행정동 base → 소속 상권 코드 목록.

    검색 단위를 행정동 base로 두는 이유는 기사 확보율이다
    ('성수1가1동'으로는 기사가 잡히지 않는다).
    """
    scores = pd.read_csv(scores_path, encoding="utf-8-sig",
                         dtype={"상권_코드": str, "행정동_코드": str})
    top = (scores.sort_values("종합점수", ascending=False)
                 .drop_duplicates("상권_코드").head(TOP_SANGWON))
    top = top.assign(행정동_base=top["행정동_코드_명"]
                     .str.replace(r"\d+가?", "", regex=True))
    return top.groupby("행정동_base")["상권_코드"].apply(list)


def expand(area: str, codes: list[str], picks: list[tuple]) -> list[dict]:
    """지역 기사를 소속 상권들로 전개한다.
    picks: (제목, 언론사, 날짜YYYY-MM-DD, 링크) 튜플 목록."""
    return [{"상권_코드": code, "행정동_base": area, "제목": title,
             "언론사": press, "날짜": date, "링크": link}
            for title, press, date, link in picks
            for code in codes]


def save(rows: list[dict], path: str = "data/news.csv") -> pd.DataFrame:
    """산출 파일 저장. 빈 결과에서도 컬럼 순서가 계약대로 유지되도록 명시한다."""
    import os
    out = pd.DataFrame(rows, columns=OUT_COLS)
    os.makedirs(os.path.dirname(path) or ".", exist_ok=True)
    out.to_csv(path, index=False, encoding="utf-8-sig")
    return out

"""scripts/scrape_news.py — data/news.csv 생성 (뉴스 담당, 【주력 경로】).

requests + BeautifulSoup으로 네이버 뉴스 검색 결과를 수집한다.

1일차 스파이크에서 확인된 문제와 해결:
  - 초기 셀렉터가 기사 제목 대신 "네이버뉴스" 버튼 라벨을 잡음 (44건 전부 동일 문자열)
  → 클래스명이 아니라 **구조 기반**으로 재설계: 제목은 경제지 도메인을 가리키는 링크 중
    텍스트 길이가 MIN_TITLE_LEN 이상인 a 태그로 판별한다.

정밀도 필터는 여기서 구현하지 않는다 — `news_filter.py`를 백업 경로와 **공유**한다.
각자 구현하면 한쪽만 고쳐지고, 두 경로의 스키마는 같은데 결과만 달라져
게이트가 그 차이를 잡지 못한다.

수집 매너: 요청 간 time.sleep(1) 이상 · 브라우저 User-Agent · 검색 첫 페이지만.
연속 실패 3회면 간격을 3초로 확대한다.

**백업 전환은 코드가 한다** (DEV_SPEC §4 아티팩트 3): 수집 완료 시점에 확보 지역이
MIN_AREAS 미만이면 `collect_news.collect_all()`을 자동 호출하고 stderr에 기록한다.
사람의 판단에 걸어두면 마감 직전에 전환이 일어나지 않는다.

사용:  uv run python scripts/scrape_news.py
출력:  data/news.csv (상권_코드, 행정동_base, 제목, 언론사, 날짜, 링크)
"""
from __future__ import annotations

import os
import re
import sys
import time
from datetime import datetime, timedelta
from urllib.parse import quote

import requests
from bs4 import BeautifulSoup

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from scripts.news_filter import (  # noqa: E402
    DAYS, MIN_AREAS, MIN_TITLE_LEN, PER_AREA, clean, expand, press_of,
    relevance, save, target_areas,
)

SLEEP = 1.0                       # 요청 간 최소 간격 (매너)
UA = ("Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
      "(KHTML, like Gecko) Chrome/126.0 Safari/537.36")

REL_DATE = re.compile(r"(\d+)(분|시간|일|주)\s*전")


def parse_date(text: str, now: datetime) -> str | None:
    """'3일 전' / '2026.08.12.' 두 형식을 YYYY-MM-DD로.

    **파싱 실패 시 None을 돌려준다.** 예전에는 오늘 날짜로 대체했는데,
    그러면 90일이 지난 기사가 오늘 기사로 둔갑해 게이트를 통과한다.
    날짜를 모르는 기사는 버리는 편이 낫다.
    """
    m = REL_DATE.search(text)
    if m:
        n, unit = int(m.group(1)), m.group(2)
        delta = {"분": timedelta(minutes=n), "시간": timedelta(hours=n),
                 "일": timedelta(days=n), "주": timedelta(weeks=n)}[unit]
        return (now - delta).strftime("%Y-%m-%d")
    m = re.search(r"(\d{4})\.(\d{1,2})\.(\d{1,2})", text)
    if m:
        return f"{m.group(1)}-{int(m.group(2)):02d}-{int(m.group(3)):02d}"
    return None


def scrape_area(area: str, now: datetime, sess: requests.Session) -> list[tuple]:
    """한 지역의 검색 첫 페이지에서 (제목, 언론사, 날짜, 링크) 상위 3건을 뽑는다."""
    since = (now - timedelta(days=DAYS)).strftime("%Y.%m.%d")
    until = now.strftime("%Y.%m.%d")
    url = ("https://search.naver.com/search.naver?where=news&sm=tab_opt"
           f"&query={quote(f'서울 {area} 상권')}"
           f"&pd=3&ds={since}&de={until}&sort=1")   # pd=3: 기간 직접 지정, sort=1: 최신순
    r = sess.get(url, timeout=10)
    r.raise_for_status()
    soup = BeautifulSoup(r.text, "html.parser")

    cutoff = (now - timedelta(days=DAYS)).strftime("%Y-%m-%d")
    out = []
    # 구조 기반 판별: 뉴스 기사 블록의 제목 링크는
    #  ① href가 경제지 원문 도메인을 가리키고
    #  ② 링크 텍스트가 실제 제목이다 ← "네이버뉴스"(6자) 버튼 라벨이 걸러지는 지점
    for a in soup.find_all("a", href=True):
        href, title = a["href"], clean(a.get_text(" ", strip=True))
        if len(title) < MIN_TITLE_LEN:           # 버튼 라벨·언론사명 제외
            continue
        press = press_of(href)
        if press is None:                        # 1) 경제지만
            continue
        block = a.find_parent(["li", "div"])
        texts = block.get_text(" ", strip=True) if block else ""
        desc = clean(texts.replace(title, " ")[:200])
        date = parse_date(texts, now)
        if date is None or date < cutoff:        # 2) 날짜 불명·90일 초과 탈락
            continue
        score = relevance(area, title, desc)
        if score == 0:                           # 3) 관련도 0 탈락
            continue
        out.append((score, date, title, press, href))

    # 같은 제목 중복 제거 (원문/네이버뉴스 이중 링크 대비)
    seen, dedup = set(), []
    for row in out:
        if row[2] in seen:
            continue
        seen.add(row[2])
        dedup.append(row)
    # 4) 관련도 높은 순 → 같은 점수면 최신순, 상위 3건
    dedup.sort(key=lambda x: (x[0], x[1]), reverse=True)
    return [(title, press, date, href)
            for _, date, title, press, href in dedup[:PER_AREA]]


def collect_all(scores_path: str = "data/scores.csv") -> list[dict]:
    """스크래핑으로 수집만 하고 행 목록을 돌려준다 (파일은 쓰지 않는다)."""
    global SLEEP
    area_to_sangwon = target_areas(scores_path)
    now = datetime.now()
    sess = requests.Session()
    sess.headers["User-Agent"] = UA

    rows: list[dict] = []
    fail = 0
    for area, codes in area_to_sangwon.items():
        try:
            picks = scrape_area(area, now, sess)
            fail = 0
        except requests.RequestException as e:
            fail += 1
            print(f"[경고] {area} 수집 실패: {e}", file=sys.stderr)
            if fail >= 3:
                print("연속 실패 3회 — 요청 간격을 3초로 확대", file=sys.stderr)
                SLEEP = 3.0
            continue
        rows += expand(area, codes, picks)
        time.sleep(SLEEP)
    return rows


def fallback_to_api(scores_path: str = "data/scores.csv") -> list[dict] | None:
    """백업 경로(검색 API) 호출. 실패하면 None — 호출부가 주력 결과를 유지한다."""
    try:
        from scripts.collect_news import collect_all as collect_api
    except ImportError as e:
        print(f"[전환 실패] collect_news 임포트 불가: {e}", file=sys.stderr)
        return None
    try:
        rows = collect_api(scores_path)
    except Exception as e:                      # API 키 미설정·한도 초과 등
        print(f"[전환 실패] 백업 경로 수집 오류: {e}", file=sys.stderr)
        return None
    print(f"[전환 완료] 백업 경로 수집 {len(rows)}건", file=sys.stderr)
    return rows


def main() -> int:
    rows = collect_all()

    # ── 백업 경로 자동 전환 (DEV_SPEC §4 아티팩트 3) ──────────────────
    n_area = len({r["행정동_base"] for r in rows})
    if n_area < MIN_AREAS:
        print(f"⚠️ 스크래핑 확보 지역 {n_area}개 < {MIN_AREAS} — "
              f"백업 경로(검색 API)로 자동 전환", file=sys.stderr)
        api_rows = fallback_to_api()
        if api_rows:
            rows = api_rows
        else:
            print(f"백업 경로도 실패 — 스크래핑 결과 {len(rows)}건으로 저장",
                  file=sys.stderr)

    out = save(rows)
    total = len(target_areas())
    n_area = out["행정동_base"].nunique() if len(out) else 0
    print(f"news.csv: {len(out):,}행 · 지역 {n_area}/{total} "
          f"· 상권 {out['상권_코드'].nunique() if len(out) else 0}개 "
          f"(확보율 {n_area/total:.0%})")
    print("→ 검증: uv run python seams/check_news.py")
    return 0


if __name__ == "__main__":
    sys.exit(main())

# seams/check_app.py — C조 앱 로직 게이트
# 화면을 검사하지 않는다. app/logic.py의 함수가 DEV_SPEC 계약대로 동작하는지만 본다.
# 이 파일이 있어야 C조 에이전트 지시서의 [수용 기준]을 기계 검사로 쓸 수 있다.
#
# 사용: uv run python seams/check_app.py [scores경로] [news경로]
#   mock으로 선착수: uv run python seams/check_app.py data/mock/scores.csv data/mock/news.csv
import os
import sys

import pandas as pd

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))


def main() -> int:
    errs = []

    try:
        from app import logic
    except Exception as e:                                   # noqa: BLE001
        print(f"import 실패: app/logic.py — {e}")
        return 1

    # 0) 로직 모듈은 streamlit에 의존하지 않는다 (분리의 전제)
    src = open(os.path.join(os.path.dirname(__file__), "..", "app", "logic.py"),
               encoding="utf-8").read()
    if "import streamlit" in src:
        errs.append("app/logic.py가 streamlit을 import — UI와 로직 분리 규약 위반")

    scores_path = sys.argv[1] if len(sys.argv) > 1 else logic.SCORES_PATH
    news_path = sys.argv[2] if len(sys.argv) > 2 else logic.NEWS_PATH
    try:
        df = logic.load_scores(scores_path)
    except FileNotFoundError:
        print(f"미산출: {scores_path} 없음 — B조 산출 전이면 "
              f"data/mock/scores.csv 로 먼저 돌린다")
        return 1

    # 1) 기본 가중치로 재계산한 값이 scores.csv의 종합점수와 일치해야 한다
    #    → build_scores.py와 app/logic.py가 같은 공식을 쓰는지의 기계 검사
    base = logic.rescore(df, 0.6, 0.4)
    merged = df.merge(base[["상권_코드", "서비스_업종_코드", "종합점수"]],
                      on=["상권_코드", "서비스_업종_코드"], suffixes=("_파일", "_재계산"))
    d = (merged["종합점수_파일"] - merged["종합점수_재계산"]).abs().max()
    if pd.isna(d) or d > 1e-9:
        errs.append(f"기본 가중치(0.6:0.4) 재계산이 파일값과 불일치 (최대차 {d}) — "
                    f"build_scores.py와 공식이 다르다")

    # 2) 극단 가중치에서 순위가 해당 지표 단독 순위와 같아야 한다
    for w, col in [((1.0, 0.0), "갭점수"), ((0.0, 1.0), "안정성점수")]:
        got = logic.rescore(df, *w).head(20)["상권_코드"].tolist()
        want = df.sort_values(col, ascending=False, kind="mergesort") \
                 .head(20)["상권_코드"].tolist()
        if got != want:
            errs.append(f"가중치 {w}에서 {col} 단독 순위와 불일치 — 가중합 구현 확인")

    # 3) 슬라이더를 둘 다 0으로 내려도 죽지 않는다
    try:
        logic.rescore(df, 0.0, 0.0)
    except Exception as e:                                   # noqa: BLE001
        errs.append(f"가중치 (0,0)에서 예외: {e} — 분모 0 방어 누락")

    # 4) 필터는 부분집합이고, 조건을 만족하며, 빈 결과에서도 죽지 않는다
    t = df["유형"].iloc[0]
    j = df["서비스_업종_코드_명"].iloc[0]
    sub = logic.filter_candidates(df, 업종=[j], 유형=[t])
    if not set(sub.index) <= set(df.index):
        errs.append("filter_candidates 결과가 부분집합이 아니다")
    if len(sub) and not (sub["유형"].eq(t).all() and sub["서비스_업종_코드_명"].eq(j).all()):
        errs.append("filter_candidates 결과가 조건을 만족하지 않는다")
    if len(logic.filter_candidates(df, 업종=[j], 유형=["존재하지_않는_유형"])):
        errs.append("없는 조건에 결과가 나온다")
    try:
        s = logic.summary(logic.filter_candidates(df, 유형=["존재하지_않는_유형"]))
        if s["후보_수"] != 0:
            errs.append("빈 결과의 summary 후보_수가 0이 아니다")
    except Exception as e:                                   # noqa: BLE001
        errs.append(f"빈 결과 summary에서 예외: {e} — 빈 상태 처리 누락")

    # 5) 뉴스 없는 상권은 예외가 아니라 빈 결과다
    news = logic.load_news(news_path)
    try:
        empty = logic.news_for(news, "0000000")
        if len(empty):
            errs.append("존재하지 않는 상권_코드에 기사가 반환된다")
    except Exception as e:                                   # noqa: BLE001
        errs.append(f"기사 없는 상권에서 예외: {e} — '기사 없음'은 정상 상태다")

    # 6) 참고 지표(아티팩트 5)는 없어도 죽지 않는다 — 게이트 없는 파일이므로
    #    "미산출이 정상 상태로 처리되는가"만 확인한다
    try:
        trend = logic.load_trend("data/__없는파일__.csv")
        if len(trend):
            errs.append("없는 추이 파일에 데이터가 반환된다")
        if len(logic.trend_for(trend, "한식음식점")):
            errs.append("빈 추이에서 결과가 나온다")
    except Exception as e:                                   # noqa: BLE001
        errs.append(f"추이 파일 미산출에서 예외: {e} — 참고 지표는 없어도 정상이다")

    # 7) 역방향 탐색은 해당 상권만, N건 이하
    code = df["상권_코드"].iloc[0]
    rev = logic.reverse_lookup(logic.rescore(df), code, n=5)
    if len(rev) > 5 or (len(rev) and not rev["상권_코드"].eq(code).all()):
        errs.append("reverse_lookup 결과가 상권/건수 조건 위반")

    if errs:
        print("\n".join(errs))
        return 1
    print(f"OK: app/logic.py 계약 준수 · {scores_path} {len(df):,}행 · "
          f"뉴스 {len(news):,}행 · 가중치 재계산 일치")
    return 0


if __name__ == "__main__":
    sys.exit(main())

# seams/check_master.py — 1단계(전원) → 2단계(B·C조) 인계 검증

           "당월_매출_금액", "당월_매출_건수", "주중_매출_건수", "주말_매출_건수",

           "연령대_20_상주인구_수", "연령대_30_상주인구_수"]

def main() -> int:
    try:  # 1) 파일 존재
        df = pd.read_csv(PATH, encoding="utf-8-sig", dtype={c: str for c in STR_COLS})
    except FileNotFoundError:
        print(f"미산출: {PATH} 없음 — 1단계 완료 전이면 정상, 2일차 오전 이후면 red")
        return 1

    errs = []
    for c in STR_COLS + REQ_NUM:                      # 2) 컬럼 존재
        if c not in df.columns:
            errs.append(f"컬럼 없음: {c}")
    if not errs:
        for c in KEY + REQ_NUM:                       # 3) 결측 (타입 검사보다 먼저)

    if errs:
        print("\n".join(errs)); return 1
    print(f"OK: {PATH} {len(df):,}행 · 상권 {df['상권_코드'].nunique()}개 "

# seams/check_news.py — 뉴스 담당 → C조 인계 검증
# DEV_SPEC §4 아티팩트 3 계약을 그대로 검사로 옮긴 것.
# 계약에 없는 검사를 추가하고 싶으면 문서에 먼저 넣는다.
#
# news.csv는 "비어 있어도 정상"인 유일한 아티팩트다 —
# 기사가 없는 상권은 앱에서 "최근 3개월 관련 기사 없음"으로 표시된다.
# 따라서 이 검사는 행 수 하한이 아니라 **담긴 행이 계약을 지키는지**를 본다.
# 다만 전량 0건이면 수집 실패이므로 red.
#
# 사용: uv run python seams/check_news.py [news경로] [scores경로]
#   mock끼리 대조: uv run python seams/check_news.py data/mock/news.csv
#   (scores 경로를 생략하면 news와 같은 디렉터리의 scores.csv를 본다)
import os
import re
import sys
from datetime import date, timedelta

import pandas as pd

PATH = sys.argv[1] if len(sys.argv) > 1 else "data/news.csv"
SCORES = (sys.argv[2] if len(sys.argv) > 2
          else os.path.join(os.path.dirname(PATH) or ".", "scores.csv"))

COLS = ["상권_코드", "행정동_base", "제목", "언론사", "날짜", "링크"]
PRESS_DOMAINS = {                       # DEV_SPEC §4 아티팩트 3 · 경제지 화이트리스트
    "hankyung.com", "mk.co.kr", "sedaily.com", "mt.co.kr",
    "asiae.co.kr", "fnnews.com", "edaily.co.kr",
}
DAYS = 90
PER_AREA = 3
DATE_RE = re.compile(r"^\d{4}-\d{2}-\d{2}$")


def main() -> int:
    try:
        df = pd.read_csv(PATH, encoding="utf-8-sig", dtype=str)
    except FileNotFoundError:
        print(f"미산출: {PATH} 없음 — 3일차 저녁 이후면 red")
        return 1

    errs = []
    for c in COLS:                                          # 1) 컬럼 존재
        if c not in df.columns:
            errs.append(f"컬럼 없음: {c}")

    if not errs:
        if df.empty:                                        # 2) 전량 0건 = 수집 실패
            errs.append("0행 — 전 지역 수집 실패. 스크래핑 차단·구조 변경 의심, "
                        "백업 경로(collect_news.py) 확인")
        else:
            for c in COLS:                                  # 3) 결측
                n = df[c].isna().sum()
                if n:
                    errs.append(f"필수 결측: {c} {n}건")

    if not errs:
        # 4) 날짜 형식·90일 이내 (하드코딩 금지 — 실행일 기준 상대 계산)
        bad_fmt = (~df["날짜"].str.match(DATE_RE)).sum()
        if bad_fmt:
            errs.append(f"날짜 형식(YYYY-MM-DD) 위반 {bad_fmt}건 — "
                        f"'N일 전' 파싱 실패 의심")
        else:
            d = pd.to_datetime(df["날짜"]).dt.date
            cutoff = date.today() - timedelta(days=DAYS)
            old = (d < cutoff).sum()
            if old:
                errs.append(f"{DAYS}일 초과 기사 {old}건 (최고참 {d.min()}) — "
                            f"기간 필터 미적용")
            future = (d > date.today()).sum()
            if future:
                errs.append(f"미래 날짜 {future}건 — 날짜 파싱 오류")

        # 5) 경제지 화이트리스트 — 링크 도메인으로 판정
        off = df.loc[~df["링크"].str.contains("|".join(
            dom.replace(".", r"\.") for dom in PRESS_DOMAINS), regex=True)]
        if len(off):
            errs.append(f"화이트리스트 외 도메인 {len(off)}건 (예: {off['링크'].iloc[0][:60]})")

        # 6) 제목 품질 — 스파이크에서 터진 실패 유형을 그대로 검사로 박는다
        short = (df["제목"].str.len() < 15).sum()
        if short:
            errs.append(f"제목 15자 미만 {short}건 — 버튼 라벨 오수집 의심")
        if (df["제목"].str.contains("네이버뉴스")).any():
            errs.append("제목에 '네이버뉴스' 포함 — 버튼 라벨 오수집")
        if df["제목"].str.contains("<b>|&amp;|&quot;|&lt;", regex=True).any():
            errs.append("제목에 HTML 태그·엔티티 잔존 — 저장 전 제거 규약 위반")

        # 7) 지역당 상위 3건
        over = (df.groupby(["행정동_base", "상권_코드"]).size() > PER_AREA).sum()
        if over:
            errs.append(f"지역당 {PER_AREA}건 초과 {over}개 조합")

        # 8) 상권_코드가 scores.csv 안에 있는지 (C조가 조인하는 키)
        try:
            sc = pd.read_csv(SCORES, encoding="utf-8-sig", dtype={"상권_코드": str})
            orphan = set(df["상권_코드"]) - set(sc["상권_코드"])
            if orphan:
                errs.append(f"scores.csv에 없는 상권_코드 {len(orphan)}개 "
                            f"(예: {sorted(orphan)[:3]}) — 조인 시 유실")
        except FileNotFoundError:
            errs.append(f"참조 실패: {SCORES} 없음 — scores 산출 후 다시 실행")

    if errs:
        print("\n".join(errs))
        return 1

    cov = df["상권_코드"].nunique()
    print(f"OK: {PATH} {len(df):,}행 · 상권 {cov}개 · 지역 {df['행정동_base'].nunique()}개 "
          f"· 언론사 {df['언론사'].nunique()}곳 · 최신 {df['날짜'].max()}")
    if cov < 30:
        print(f"⚠️ 경고(red 아님): 기사가 붙은 상권 {cov}개 — 시연 상권에 기사가 있는지 확인할 것")
    return 0


if __name__ == "__main__":
    sys.exit(main())

            if n:
                errs.append(f"필수 결측: {c} {n}건")
    if not errs:                                        # 3) 값 형식·유일성·규모
        if df.duplicated(subset=KEY).any():
            errs.append(f"유일 키 중복: {df.duplicated(subset=KEY).sum()}건")
        bad = set(df["유형"].unique()) - TYPES
        if bad:
            errs.append(f"정의 외 유형: {bad}")
        # 이 파일은 후보 목록이다 — 공급 과잉 조합이 섞이면 프로젝트 목적과 어긋난다
        if (df["공급갭"] <= 0).any():
            errs.append(f"공급갭 0 이하 {(df['공급갭'] <= 0).sum()}건 — "
                        f"scores.csv는 공급갭 > 0 인 행만 담는다")
        # 상한이 아니라 정확값으로 본다 — 화이트리스트 누락은 초과가 아니라 미달로 나타난다
        n_jong = df["서비스_업종_코드"].nunique()
        if n_jong != JONG:
            errs.append(f"업종 수 불일치: {n_jong} != {JONG} "
                        f"— config/업종_whitelist.csv 적용 확인 "
                        f"(미달이면 화이트리스트 누락, 초과면 미적용)")
        for c in ["갭점수", "안정성점수", "종합점수"]:      # 방향 통일 검사
            if not df[c].between(0, 1).all():
                errs.append(f"{c} 0~1 범위 벗어남 (min-max 정규화 확인)")
        # 유효수요는 minmax 3종을 가중치 합으로 나눈 값이라 0~1이다 (§5-3).
        # 벗어나면 log1p / minmax / 합 나누기 중 하나가 빠졌다.
        if not df["유효수요"].between(0, 1).all():
            errs.append(f"유효수요 0~1 범위 벗어남 "
                        f"(min {df['유효수요'].min():.3f}, max {df['유효수요'].max():.3f}) "
                        f"— §5-3의 log1p·minmax·가중치합 나누기 확인")
        if (df["유효수요"] <= 0).any():
            errs.append(f"유효수요 0 이하 {(df['유효수요'] <= 0).sum()}건 "
                        f"— 공급밀도의 분모다. 인구 0 상권 제외 확인")
        # log1p 누락 자동 검출: 원단위 min-max면 극단 분포가 그대로 남아
        # 중앙값이 0.05 밑으로 눌린다 (직장인구 중앙 494 vs 최대 199,667)
        med = df["유효수요"].median()
        if med < 0.05:
            errs.append(f"유효수요 중앙값 {med:.4f} — log1p 누락 의심. "
                        f"원단위 정규화하면 값이 0 근처로 눌려 지표가 사라진다 (§5-3)")
        # 안정성 방향 반전 검사: 폐업률과 안정성점수는 음의 관계여야 한다
        corr = df["행정동_폐업률"].corr(df["안정성점수"])
        if pd.notna(corr) and corr > 0:
            errs.append(f"안정성점수 방향 오류: 폐업률과 양의 상관({corr:.2f}) — "
                        f"'1 - 정규화' 반전 누락")
        if len(df) < MIN_ROWS:
            errs.append(f"행 수 미달: {len(df):,} < {MIN_ROWS:,}")

    if errs:
        print("\n".join(errs)); return 1
    print(f"OK: {PATH} {len(df):,}행(후보) · 유형 {df['유형'].nunique()}종 "
          f"· 업종 {df['서비스_업종_코드'].nunique()}종 · 상권 {df['상권_코드'].nunique()}개 "
          f"· 유효수요 중앙 {df['유효수요'].median():.3f}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
